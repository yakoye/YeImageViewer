## 路线与验收闸门

1. M0：审计、保留全部需求及259用例、记录存储/抓屏限制。
2. M1：快速 HUD、桌面采样、取消/复制/格式/坐标/细移/冻结、偏好、工具栏；补全主程序及可配置全局热键、实时后端、受限桌面与硬件矩阵。
3. M2：统一当前色、图片原始 RGBA 逆变换、色轮与全格式字段、推荐色、原色/撤销事务。
4. M3：永久历史、搜索筛选、来源/UTC/parent、隐私、撤销删除、导入导出、备份/迁移/多实例及5000条压力。
5. M4：核许可后接入五套 UI 色库；图片提色；传统色；渐变；三类收藏及导出。
6. M5：离线规则配色、UI角色、WCAG、CSS/JSON。
7. M6：最后接入显式授权的可配置 AI，凭据入 Windows 凭据库，默认不联网。
8. M7：259用例逐项归档、完整回归、候选绿色包复验、双归档逐文件哈希；没有硬件的项目标 BLOCKED。

每批只把真实完成的子阶段标为完成，不能把几何单元测试换算成多屏实测，也不能将第一批 HUD 候选当成完整助手。未实现的页面不展示可点击占位入口。

## ADR-001：先用明确标记的快照会话建立安全路径

初始源帧在任何覆盖层出现前抓取；每块监视器独立 DIB，避免虚拟桌面空洞浪费内存/误采。覆盖层绘制只读源帧，HUD绝不写回源缓存。快照模式明确显示，F5/空格隐藏全部覆盖层、等待桌面合成后重抓，失败后不允许复制旧像素。后续实时捕获必须单独验证排除自身，不把 GDI 快照包装成实时。

微软说明 `WDA_EXCLUDEFROMCAPTURE` 只在 Windows 10 2004及以后支持，旧系统可能变成黑色内容；因此不能单凭 API 返回成功就启用实时。参考：[官方文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)。受保护内容/安全桌面不绕过；不凭“像素是黑色”判断捕获失败。

## ADR-002：偏好与永久历史分离

快取偏好存于 EXE 同目录 `YeImageViewer.color-picker.ini`，包含模式/格数/倍率/坐标显示等，不存实际颜色、截图或采样坐标。严格版本解析，临时文件写完并 Flush 后原子替换；失败保留旧文件并在HUD报告。只读目录不静默换存储位置。后续历史使用独立版本化事务存储，并专门处理迁移、备份和并发；不能让频繁颜色写入破坏现有 DB 的固定头和其他文本配置。

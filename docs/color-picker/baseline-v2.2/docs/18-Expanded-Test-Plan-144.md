## 测试原则

- 实施人按照 Case 中的步骤准备真实样本、截图/日志/哈希作为 Evidence；每条要有单独可追踪状态。
- 自动测试优先使用现有 C++ UT 框架并尽量由构造的合成 PSD 文件生成确定像素对照；真实 Photoshop 比对需人工或经验证的基准 PNG。
- `PASS` 仅限实际执行并符合预期；不能执行写 `BLOCKED`/`NOT_RUN`，不能把“计划覆盖”写成“通过”。
- 原 v2.0 所有色值转换、历史记录、多屏 DPI、色卡、渐变、收藏、配色等用例必须全量回归。
- 性能指标先记录用户机基线（文件大小、层数、PSB/PSD、耗时、内存）再设置门槛，不编造未测性能数字。

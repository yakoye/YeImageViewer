## 版本管理

- 不擅自改现有YeImageViewer版本号；先查当前tag/manifest，使用每轮递增的`-rc1/-rc2`形式；只有测试通过再升stable。
- 任何未实现功能必须有REQ、Issue和预定迭代，不准从需求文档或导航里删掉；AI如经用户明确取消才更新范围变更记录。
- 各阶段都要更新`docs/`：PRD、设计、test cases、**真实**test report、bug tracker、CHANGELOG、roadmap、需求追踪矩阵、发布清单。
- 每个新增功能至少一条可复现测试；每个Bug补回归测试；不运行的测试统一NOT_RUN。

## 停止条件与风险

- 采样不精确、HUD影响屏幕原图、混合DPI取错、退出有残留、历史损坏文件/泄露隐私等问题为阻断缺陷，不可直接跳过阶段。
- 无法实测的环境（HDR/特定RDP/第三方特殊保护应用）记BLOCKED并说明限制，不可虚报PASS。
- 色库/第三方代码无适当授权时替换为许可兼容的数据，不复制未知授权静态资源。

# 15 · 旋转/镜像及保存：明确区分“浏览状态”与“文件修改”

## 现有实现需要兼容
仓库 `YeImageViewer/include/RotationStore.h` + `src/RotationStore.cpp` 按路径存储0～3次90度旋转，并把设置写入 YeImageViewer.db 文本配置区；README 已写明“旋转方向会按图片路径自动保存”。因此**不能直接把旧的自动记忆行为删掉而声称只是改变提示**。需要保留旧数据兼容与用户可理解的浏览方向持久化能力。

## 状态/动作
- `PreviewTransform`: 当前视图的旋转/水平镜像/垂直镜像矩阵，是视觉变换，不立刻写入原文件。
- `RememberViewOrientation`: 记住该图片的浏览方向（修改 YeImageViewer.db/等效配置），与文件本身无关；旧版旋转数据迁移无损，默认遵循旧版“旋转记忆”策略。
- `ExportTransformedCopy`: 将当前画面按指定变换编码为**新文件**，采用独立保存对话框、格式/编码/ICC/EXIF/Alpha 保持策略，不得静默覆盖。
- `ReplaceOriginal`: 明确二次确认+备份/原子替换+撤销能力之后才考虑开放。PSD/PSB/PSDT、RAW、动画、多帧、Live Photo 等格式默认不开放覆盖原文件。

## 轻量操作 Toast（不模态）
示例：`↻ 已旋转 90° · 浏览方向已记住  |  [保存副本 Ctrl+Shift+S]`。
如镜像未持久化：`⇆ 已水平镜像 · 仅当前浏览  |  [保存副本 Ctrl+Shift+S]`。
`[保存副本]`必须可点击，快捷键可通过软件设置配置并防冲突（仅示意，Codex 审计现有键位后决定默认）。持续 ~4–7 s 用户可调整；重复连续旋转时合并提示、不排队阻塞。对键鼠可达、焦点/屏幕边界/多显示器、上下文菜单同一动作统一封装。

## 保存算法要求
- Q/E/工具栏旋转与镜像应在视图矩阵中组合，组合顺序有数学定义；不同操作顺序不能错误交换。四次90°回到原始；水平+垂直效果等价180°像素结果但元数据保留实际操作状态。
- 输出宽高在90°/270°时交换，像素映射必须全覆盖不越界；保证无意重编码时不声称无损。
- JPEG 可选择支持真正的 lossless JPEG transform（受 MCU 对齐限制），否则有损编码明确提示；需要避免重复损失。
- 保存 EXIF orientation 应正规化，否则双重旋转；保留/选择保留 ICC、XMP、时间戳等信息并验证；PNG/TIFF/Alpha 与动画/多页格式测试。
- 安全写入：在目标目录生成临时文件，完整成功并验证后原子更名；遇到占用/无权限/磁盘不足时，源文件和 UI 预览保持完好。
- **PSD 特例**：仅导出已显示的单帧画面副本，绝对不把扁平文件写回同名 PSD、冒充保留分层。

## 兼容性开关
设置中提供“旋转后记住浏览方向(默认继续兼容旧版)”和“变换后显示保存提示”，镜像是否记忆从具体实现能力确认后再启用。旧数据迁移带测试，避免旧用户已记忆的角度丢失。

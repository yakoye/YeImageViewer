## 1. 用户场景与范围

### 1.1 最典型的三条路径

**路径 A：3 秒内取得屏幕颜色**

1. 在任意软件（浏览器、设计软件、桌面等）看到目标颜色。
2. 从 YeImageViewer 工具栏、菜单或可配置的全局快捷键启动屏幕取色。
3. 屏幕出现十字放大镜，移动鼠标定位像素。
4. 左键或 Enter 确定：**复制默认色值到剪贴板 + 写入历史 + 提示成功**。不强制弹出大型助手窗口。
5. 可以单击取色后的轻量提示里的“调整”，继续修改。

**路径 B：取色后细调颜色**

1. 完成屏幕取色后，点“调整”，或在颜色助手打开已有颜色。
2. 在色轮/色板或 HEX/RGB/HSL/HSV 输入框中调整，实时查看当前预览与原色对比。
3. 可以撤销/重做、恢复原色、复制任何格式。
4. 点击“应用/保存到历史”确认调整；“取消”不污染历史。
5. 可以将当前调整结果收藏，稍后继续使用。

**路径 C：找回之前的颜色**

1. 打开颜色助手 → “历史”。
2. 按最近取色顺序查看色块、色值、时间、来源类型和可选坐标。
3. 一键复制、再次调整、收藏，或删除选定记录。
4. 重启 YeImageViewer 后仍可看到记录。

### 1.2 范围边界：不要混淆两种取色

| 模式 | 从哪里读取 | 结果含义 | 阶段 |
|---|---|---|---|
| **屏幕取色 Screen Picker** | Windows 当前桌面各显示器可获取的显示内容 | 截屏时已经合成/转换后的像素 RGB；屏幕没有透明度 | **P0** |
| 图片取色 Image Picker | YeImageViewer 已解码图片缓冲区 | 图片源 RGBA / 颜色信息；需要处理缩放旋转与透明度 | P2，可提前复用现有图像像素接口 |

**P0 的全屏取色绝不等于“只在 YeImageViewer 窗口内部取色”。** 要覆盖普通桌面上的其他软件、任务栏和多个显示器；Windows 安全桌面、受保护视频、DRM、防截屏窗口等系统限制必须如实提示，不承诺绕过。

### 2.1 可确认的实现线索

| 事项 | 包内证据 | 对 YeImageViewer 的意义 |
|---|---|---|
| 取色入口 | `plugin.json` 的 `pickercolor` 和 `window.utools.screenColorPick(...)` | **不能直接调用**，YeImageViewer 必须自建 Windows 采样后端与取色 HUD |
| 颜色编辑 | 已编译 JS 中有色轮、`HEX/RGB/HSV/HSL/CMYK/HSI/LAB` 字段和颜色计算逻辑 | 参考信息布局和交互；自行实现可测试的颜色数学 |
| 配色 | 补色、类似色、三色/四色方案等实现线索 | 不需要 AI 即可做传统色彩关系推荐；可列入 P2 |
| UI 色卡 | Flat / Fluent / Open / Ant / Material 标签 | 作为后续色卡页的信息架构参考，数据许可分别核实 |
| 收藏 | `window.utools.db` / `dbStorage`，存在收藏、排序线索 | YeImageViewer 必须采用自己的可迁移、可备份存储 |
| 图片色卡 | `window.utools.screenCapture` 等 uTools 相关调用 | 单独重新设计 Win 原生实现；非首版重点 |
| 取色历史 | 颜色页存在最多 6 个当前颜色的临时数组；**未找到可据此确认的持久化历史** | 需要设计正式的独立 HistoryStore，不可仅保留最近六项 |
| AI | `plugin.json` 有 `ai` 功能入口 | **P3 最后做 / 可以完全不做** |

### 2.2 复用原则

- **允许参考**：功能清单、窗口结构、配色分类、快捷键体验、算法名称、数值显示样例。
- **不得假定可直接复用**：插件 JS/CSS、图片、图标、独家色表、UI 品牌样式和任何未明确授权的数据。
- 若使用 `chroma.js` 一类颜色数学库、色轮组件或色表，请先确认项目技术栈、明确授权、打包方式和依赖大小；**禁止为了一个吸管按钮引入整个 Electron/React/uTools 运行时**。
- 目标是在现有 YeImageViewer 中新增原生体验，而不是把 uTools 插件嵌入一个浏览器窗口。

## 3. 阶段优先级：以这三件事为中心

| 阶段 | 必须交付 | 暂不做 | 验收关口 |
|---|---|---|---|
| **P0：全屏快捷取色** | 工具栏/菜单入口、全屏任意普通区域、放大镜、坐标/格式切换、跨屏/DPI、复制、错误恢复、提交事件记录最小接口 | 复杂色轮、色卡、AI | P0 对照关键色块与多屏测试合格 |
| **P1a：颜色调整** | 简洁颜色工作台、色轮和滑块、HEX/RGB/HSL/HSV 双向编辑、比较原色/新色、撤销/重做、复制/应用 | 传统色、渐变库、AI | 输入、拖动和复制值相符，无精度漂移 |
| **P1b：取色历史** | SQLite/JSON 持久化方案、最近记录、复制、再编辑、删除/清空确认、搜索/过滤、去重策略、损坏恢复、隐私设置 | 云同步、AI | 多次重启、异常关闭不丢已提交数据 |
| **P2：进阶工具** | 图片像素取色、收藏、推荐配色、UI 色卡、传统色、渐变色、图片提色、调色板导出、可访问性对比度 | AI | 每个新增页面有自动化/手测用例 |
| **P3：可选 AI** | 仅在用户明确要做时增加自然语言配色和自选服务 | 默认在线调用、上传截图 | AI 故障时前三项仍完整可用 |

> **建议交付方式**：P0 → P1a → P1b。由于用户把历史列为前三项，不能把 P1b 拖到“有空再做”的长期规划中。P0 可以先建 `HistoryStore` 接口或极简历史落盘，P1b 再补齐完整界面。功能稳定优先于一次开发七个页面。

## 4. P0：全屏快捷取色器详细规格

### 4.1 入口及快捷键

| 操作 | 默认要求 |
|---|---|
| 工具栏 | 增加“吸管/取色”图标；沿用 YeImageViewer 的图标尺寸、悬浮提示及工具栏排布，不打乱原按钮 |
| 菜单 | “工具 → 屏幕取色”，并支持从图片右键菜单/相关现有入口接入（以现有菜单架构为准） |
| 程序内快捷键 | 先检查现有映射再分配；在帮助/设置中显示，允许修改 |
| 系统全局快捷键 | **默认关闭**，用户可主动启用并录制组合键；注册失败要显示冲突原因与恢复办法 |
| 重复调用 | 激活同一个取色会话，不创建第二份覆盖层；禁止不断创建采集线程 |
| 退出 | Esc 取消；右键取消；程序被关闭或屏幕拓扑变化时安全释放资源 |

不得抢占系统保留组合键，不得改变 YeImageViewer 原有“鼠标右键退出”、“精细拖动 Shift”等既有可配置行为。**取色模式快捷键只在取色模式下有效**；取色结束恢复全部原事件处理。需要系统级快捷键时使用 `RegisterHotKey` 等合适机制，并完整处理注册/注销、注销失败和程序崩溃恢复。

### 4.2 放大镜 HUD（参考图 1）

建议紧凑布局：

```text
┌─────────────────────────┐
│ 像素网格 15 × 9         │
│        ╋                │ ← 中心一像素明显高亮；横/竖辅助线
│                         │
├─────────────────────────┤
│ 屏幕(绝对) (-318, 811)   │
│ ■  #53CAA4             │
│ Shift: 颜色格式         │
│ C: 复制  P: 坐标模式    │
└─────────────────────────┘
```

**行为要求：**

1. 网格显示鼠标周围**真实物理像素**，默认建议 `15列 × 9行`（列/行均为奇数），每格可放大 `10～14 DIP`，中心必须唯一且与当前采样像素严格一致。
2. 横纵辅助线、中心边框使用高对比度显示；不能因浅色背景而看不清，可采用双描边或阴影。
3. 展示**当前显示器标识、坐标模式、坐标数字、颜色块、色值格式和值**。UI 尽量小，且不会盖住准星所指像素。
4. 像素格边界使用明确的 1px 分隔线；取样应以真实原始像素为准，不能从放大后的 UI 反采样。
5. 鼠标移动实时更新；缓慢移动、移过显示器边缘、停留和快速移动都不能出现像素错位。
6. 可选鼠标滚轮调节放大倍率（建议 6×～24×），但必须先确认不会干扰原软件快捷键与滚动行为；工具提示显示当前倍率。
7. HUD 位置要自动选择：优先鼠标右下；右边不足放左侧；下边不足放上方；多屏以**HUD 所在屏的工作物理边界**计算；必须防止跨屏被裁剪。
8. 截图边界不够 15×9 格时，越界格绘制为棋盘或不可用占位，**不得裁剪后使中心偏移、访问无效内存或取到其他显示器错误数据**。
9. 高 DPI 下网格尺寸、文字和触控区域按 DIP 绘制，**采样坐标按物理像素计算**；不能用逻辑坐标替代像素下标。
10. HUD 应明确当前为“截屏瞬间的像素”或“实时采集”，不得让 UI 显示的颜色和实际采样帧不同步。

### 4.3 坐标模式（`P` 切换）

**明确采用以下两套坐标定义：**

- **屏幕绝对坐标**：Windows 虚拟桌面的**物理像素坐标**，以主显示器原点为参考；副屏在主屏左边/上方时可能是负数，例如 `(-318, 811)`。
- **显示器相对坐标**：`(当前像素X - 当前显示器Left, 当前像素Y - 当前显示器Top)`；当前显示器的左上角是 `(0,0)`，不受主副屏布局影响。
- 切换时颜色不变、采样点不变，**仅数值和标签变化**。屏幕取色界面不得把“相对”误解为 YeImageViewer 客户区坐标；未来图片取色再单独提供“图片原始坐标”。
- 可选复制坐标，格式例如 `(-318, 811)` 或 `Display 2: (162, 811)`；是否复制坐标由用户显式选择，不影响默认颜色剪贴板内容。

### 4.4 颜色格式（`Shift` 循环）

| 格式 | 示例 | 取色器要求 |
|---|---|---|
| HEX | `#53CAA4` | **默认**；支持设置是否含 `#`、大小写 |
| RGB | `rgb(83, 202, 164)` | 可显示、可复制 |
| HSL | `hsl(161, 53%, 56%)` | 可显示、可复制（数值以统一转换库为准） |
| HSV/HSB | `hsv(161, 59%, 79%)` | 可显示、可复制 |
| HEX8 / RGBA | `#53CAA4FF` / `rgba(83, 202, 164, 1)` | 屏幕色 Alpha 恒为 255，可通过设置加入循环；图片取色 P2 再使用真实 Alpha |
| CMYK / HSI / CIE-LAB | 如 `CMYK(59%, 0%, 19%, 21%)` | 主颜色工作台展示；P0 HUD 可放“更多格式”菜单，不强行挤占循环顺序 |

要求：显示格式与复制格式始终一致；格式切换不触发重新采样；复制不会偷偷加换行；对用户手输的 `#`、HEX 大小写偏好持久化。

### 4.5 取色状态与操作

```text
IDLE
  └─启动→ CAPTURING ──成功→ PICKING
                      └─失败→ ERROR → IDLE
PICKING
  ├─移动鼠标/按方向键→ UPDATE_SELECTION
  ├─Shift→ CHANGE_FORMAT → PICKING
  ├─P→ CHANGE_COORD_MODE → PICKING
  ├─C→ COPY_CURRENT（成功复制则确认该次取色）→ PICKING
  ├─左键/Enter→ COMMIT + COPY + HISTORY → RESULT → IDLE
  ├─E 或结果提示“调整”→ COMMIT + OPEN_EDITOR
  ├─R→ REFRESH_SNAPSHOT → PICKING
  ├─Esc/右键→ CANCEL → IDLE（不新增历史）
  └─进程退出/显示器异常→ CLEANUP → IDLE
```

**快捷键建议（只在 PICKING 中生效）：**

| 键/操作 | 行为 |
|---|---|
| 鼠标移动 | 更新采样点 |
| 方向键 | 每次移动 **1 物理像素**；`Ctrl + 方向键` 可选为 10px，严格限于真实显示器边界 |
| 左键 / Enter | 确认 → 写剪贴板 → 写历史 → 退出取色 |
| `Shift` | 切换 HEX / RGB / HSL / HSV 等格式；必须避免 Shift 长按连续滚动，**每次按下仅切换一次** |
| `P` | 绝对 / 显示器相对坐标切换 |
| `C` | 复制当前颜色但继续取色；这属于一次明确的成功取色操作，**也应写历史**；同一会话中重复按 C 写入行为见去重规则 |
| `E` | 将当前颜色送入编辑器（在打开编辑器前提交一次取色记录） |
| `R` | 重新截取当前桌面快照，用于网页变化或动画画面；捕获时确保不把 HUD 自己截进去 |
| `Esc` / 右键 | 取消且不记录未提交的预览色 |
| 滚轮 | 可选放大倍数；在 HUD 范围内显示提示 |

### 4.6 完成取色后的轻量提示

**默认不弹出占据屏幕的大窗口。** 成功取色后在 YeImageViewer 或鼠标附近合适位置（以不抢焦点为前提）显示一个可操作的短暂结果面板：

```text
[■] #53CAA4     ✓ 已复制
    [调整]  [历史]  [再取一次]
```

- 默认结果提示自动消失（建议约 5 秒，可配置/关闭），**操作按钮真实可点**；不因动画或提示窗口阻塞其他软件输入。
- “调整”将取到的颜色带入颜色工作台；“历史”打开历史并定位新记录；“再取一次”重新进入取色。
- 用户可在设置中选择取色完成动作：`仅复制+轻提示（默认）` / `打开紧凑颜色调整` / `打开完整颜色助手`。
- 复制失败应明确提示且可以重试；**历史是否保存**应按提交事件独立处理，不可将复制失败误报为整个取色成功。
- 启动取色前记住当前活动窗口/显示器；结束后尽可能恢复适合的窗口焦点，避免把用户强行拉到 YeImageViewer 主窗。

### 4.7 屏幕边界与多显示器（重点验收项）

必须测试：

- 单屏四个角、四条边与距边缘 1px/2px。
- 两个显示器水平、垂直和 L 形布局；主屏左右互换，存在虚拟桌面“空洞”。
- 副屏坐标为负；扩展/仅主屏之间切换；显示器临时断开、重新连接。
- Windows 缩放 100%、125%、150%、200%，尤其同一机器上的混合 DPI。
- 不同分辨率与刷新率；竖屏；任务栏在另一屏；多屏分辨率相差明显。
- RDP、全屏普通软件、跨屏移动、高刷新率场景；某些系统保护区域不可采样要可解释。
- Win + P 切换显示器时取色器必须退出或重新初始化，不能留在无效物理区域。

### 4.8 屏幕采样技术方案（先按仓库技术栈选实现）

**强制约束：**

1. 启动时检查进程 DPI 感知模式（最好 Per-Monitor V2，需审查现有 manifest/进程设置）；**不允许为了取色随意破坏整程序高 DPI 行为**。
2. 用 Windows 虚拟桌面物理边界和 `HMONITOR`/显示器信息管理屏幕，统一屏幕坐标与每屏相对坐标，包含负坐标。
3. 采样后端优先做**可测试的桌面截图快照模式**：屏幕像素采样逻辑与 HUD UI 完全分离；HUD 出现前完成截图，避免采到自己的浮层、阴影和准星。
4. 快照模式要保证**鼠标所见截图与取样缓冲区是同一帧**：建议显示冻结截图作为桌面覆盖背景，或设计能清楚标明冻结帧的 UI。不得采一帧旧图却展示动态桌面并声称是实时值。
5. `R` 再次截图时，应隐藏或排除 HUD 及结果提示，刷新完成后再显示；禁用“从 HUD 自己获取像素”的错误实现。
6. 首选与当前代码和运行平台相符的 Win32 GDI/其他经验证的屏幕捕获后端。GDI 的 `BitBlt`（必要时研究 `CAPTUREBLT`）可以作为第一版候选；DXGI Desktop Duplication / Windows Graphics Capture 仅在需要时增加，且应具备降级机制。
7. 不同显示器的帧缓冲可以独立管理，避免虚拟桌面大范围空洞导致过度内存分配；像素存储明确 BGRA/RGBA、行跨度、原点，统一转换为供 UI/数学库消费的 sRGB-like RGBA 数据。
8. 内存和资源由 RAII/现有项目机制管理；每次创建的 HDC、HBITMAP、D3D 对象、句柄、热键、鼠标捕获、浮层窗口必须可靠释放。
9. 严禁后台常驻截屏；**只有主动取色操作期间**才进行采集。不得自动上传截图、所取像素、窗口标题、路径或历史。
10. HDR、ICC 广色域的物理显示色值与常规 SDR 8-bit 截屏结果可能不同。首版必须以**“采集到的桌面像素（通常为 SDR/sRGB 近似）”**描述结果；标明限制，不假称专业级色度测量精度。
11. 对安全桌面、UAC 提权对话框、DRM、防截屏等**系统限制**采用失败提示/空白像素处理；不尝试绕过安全机制。

## 5. P1a：取色后的颜色调整（第二优先级）

### 5.1 页面结构

建议首版颜色助手采用**最少必要的三个入口**：`颜色调整`、`取色历史`、`收藏`（收藏可 P2 完善）。暂不为了模仿参考图硬塞七栏；后续功能逐步开放。

```text
┌─ YeImageViewer · 颜色助手 ──────────────────────────────────┐
│ 颜色调整     取色历史     收藏（P2）                        │
├─────────────────────────────────────────────────────────────┤
│ 当前色大色块           HEX        [#53CAA4]   [复制]       │
│ 取色前后对比           RGB        [83,202,164] [复制]       │
│ 色相环/调色区域        HSL        [...]       [复制]       │
│ Hue 滑块               HSV/HSB    [...]       [复制]       │
│ 饱和度/亮度滑块        CMYK / HSI / CIE-LAB [展开]         │
│ Alpha（图片色 P2）     [恢复原色] [撤销] [重做]            │
│                      [重新取色] [收藏] [取消] [应用]       │
└─────────────────────────────────────────────────────────────┘
```

**参考图 2/3 重点借鉴功能，不逐像素照搬样式。** 窗口的拖动、最小尺寸、缩放、深色/浅色/跟随系统、图标和按钮应复用 YeImageViewer 统一规范。允许颜色助手独立打开，不要求 YeImageViewer 先打开一张图片。

### 5.2 颜色模型与数值联动

内部状态必须使用**单一规范颜色值**（建议 `RGBA8` + 来源色彩空间元数据；可用浮点中间态）；HEX/RGB/HSV/HSL 等均从同一状态计算，避免每个文本框互相独立导致越改越偏。

| 功能 | P1a 要求 |
|---|---|
| HEX 编辑 | `#RGB`、`#RRGGBB`，必要时 `#RRGGBBAA`；合法输入归一化；不合法不覆盖有效状态 |
| RGB 编辑 | `R/G/B` 范围整数 0～255；可输入 `rgb(…)`；校验与规范化 |
| HSL 编辑 | `H` 0～360° 取模、`S/L` 0～100%；编辑任一值更新预览/其余字段 |
| HSV/HSB 编辑 | 与 HSL 同级的可编辑输入；`V/B` 0～100%；没有饱和度的灰色要稳定处理 Hue |
| 色轮 / 滑块 | 鼠标/键盘拖动实时预览；中心颜色选点、色相/饱和度/明暗显示明确 |
| CMYK | P1a 至少只读显示和复制，注明**无印刷 ICC 配置的近似 CMYK**；可靠的双向编辑可 P2 |
| HSI | P1a 只读展示与复制或 P2 才加入；不能用 HSV 假冒 HSI |
| CIE-LAB | P1a 只读展示与复制或 P2 才加入；明确 `CIELAB D65`，越界色需标注 |
| Alpha | 屏幕取色默认 255，图片色以后支持真 Alpha；透明色用棋盘格背景对比 |
| 原色/新色 | 双色块并排，任何时候可一键“恢复原色”；不覆盖最初所取样本 |
| 撤销/重做 | 历史仅针对当前编辑会话，建议 `Ctrl+Z/Ctrl+Y`；拖动时每次完整拖拽算一次撤销动作，**不是每个鼠标像素都写入堆栈** |
| 实时复制 | 每种格式右侧复制按钮；主复制按用户当前默认格式；复制后内容与当前颜色一致 |
| 应用/取消 | 应用创建一次“调整提交”历史；取消完全不改变既有历史和已收藏的颜色 |

**编辑中的非法输入**：例如 HEX 输入到 `#12` 的中间过程，应保留文本供继续输入，不让颜色突然变黑或循环改写光标；失焦/Enter 进行合法校验；提示错误而不是悄悄变更。

**精度策略**：内部数值规范化只在必要转换/显示时舍入，拖动同一个点、切换多个显示格式不应逐次累计误差；`RGB → HSL → RGB` 对 8-bit RGB 通道误差目标不超过 1（典型测试），使用单元测试校验。

### 5.3 快捷调整及配色辅助

P1a 优先：

- 色相、饱和度、亮度/明度等直接调节，支持滑块细调与键盘步进（方向键 1 步，Shift+方向键可选 10 步）。
- 预览区支持当前颜色应用到亮背景/暗背景，便于快速判断视觉效果。
- 最近一次“屏幕取色”可以一键重新打开吸管并回填编辑器。
- 可选支持“锁定色相”“锁定饱和度”“锁定亮度”，但不应影响 P1a 进度。

P2 再加：互补色、类似色、三角色、分裂互补色、四色方案、单色深浅系列、WCAG 对比度与文本颜色建议等。**这些都是本地计算，不依赖 AI。**

### 5.4 是否打开调整面板：以速度为核心

默认路径为“屏幕取色 → 复制 → 轻量结果提示”，但必须随时有**一键进入调整**入口；用户如果选择“取色后自动打开调整”，就要直接将本次色值显示在紧凑工作台中（不再点第二次按钮）。

## 6. P1b：取色历史（第三优先级，但属于核心功能）

### 6.1 必须持久保存的信息

建议历史结构（字段可按现有工程习惯命名）：

```json
{
  "id": "generated-unique-id",
  "schemaVersion": 1,
  "type": "screen-picked",
  "rgba": { "r": 83, "g": 202, "b": 164, "a": 255 },
  "formattedAtCommit": "#53CAA4",
  "formatAtCommit": "HEX",
  "createdAt": "2026-10-20T11:00:00+08:00",
  "source": "screen",
  "displayId": "display-stable-key-if-available",
  "screenPointPx": { "x": -318, "y": 811 },
  "relativePointPx": { "x": 162, "y": 811 },
  "parentRecordId": null,
  "repeatCount": 1,
  "note": ""
}
```

说明：上面只是**结构示例，不得将样例值当作真实采样结果**。采用 UUID/其他稳定唯一 ID；日期可按 UTC ISO-8601 存储，显示为本地时间；多显示器标识不能假设 Windows 的“显示器 1”编号永远不变。色彩模型保留原始 RGBA，而不是只保存显示字符串，这样切换 HEX/HSL 时不用丢精度。

### 6.2 记录时机：防止历史被拖动污染

| 用户动作 | 是否写历史 |
|---|---|
| 鼠标在屏幕移动预览 / 切格式 / 切坐标 | **否** |
| 屏幕取色左键/Enter 确认 | **是，写一次** |
| 在取色器按 `C` 成功复制 | **是**；同一次会话内同像素、同 RGBA、短时间重复按 C 可合并计数 |
| `E` 进入调整面板 | **是，源色写一次**；与同会话刚写入的样本合并 |
| 调整时拖色轮/修改未提交的输入 | **否** |
| 调整后点击“应用” | **是，新建 type=`adjusted` 记录**；保留来源 `parentRecordId` |
| 复制历史记录中的已有颜色 | **否**；可更新 `lastUsedAt`，但不应凭空增加一次“取色” |
| 取消调整 / Esc 取消取色 | **否** |
| 对同一历史条目点收藏 | **否**；进入独立的收藏存储 |

**去重策略**：不要把所有相同 HEX 永久合并——用户不同时刻再次取得同色仍有意义。默认只对**同一会话、相同颜色、相同采样坐标、极短间隔**的重复提交做合并；其他保留原记录。合并时可递增 `repeatCount` 并更新时间；可配置关闭去重。不得靠 UI 重渲染重复插库。

### 6.3 历史列表交互

- 默认**最新在前**；一行包含色块、HEX（或用户当前选定格式）、复制图标、相对时间/精确时间、屏幕/图片/调整来源标识。
- 点击记录：主调整面板加载这一颜色；不覆盖历史中的原数据。
- 每行快捷操作：`复制`、`调整`、`收藏`（P2）、`删除`、`更多格式复制`。
- 支持搜索：HEX 精确/模糊匹配、RGB 文本、可选备注；支持来源筛选和时间顺序。
- 相同颜色可以在不同日期重复出现；显示完整历史，不强行只保留 6 个色块。
- 默认建议最多**保留 500 条**，用户设置可改为 100/500/2000；达到上限时只清理**最早非收藏的历史条目**。收藏库绝不因历史容量自动删除。
- “清空历史”必须弹出确认，说明会删除历史、不删除收藏；支持取消。单条删除应有撤销提示或二次确认机制，避免误删。
- 历史列表支持键盘上下选择、Enter 打开调整、Ctrl+C 复制所选值；避免和编辑框内复制冲突。
- 空状态：显示“暂无取色记录”，提供“开始屏幕取色”；不必照搬参考图的空白大窗口。

### 6.4 存储、安全与迁移

- 首选沿用 YeImageViewer 现有设置存储风格。少量数据可用带版本的 JSON + 临时文件写入/原子替换；若已存在 SQLite 基础设施，可优先用 SQLite 事务。**选择其一并说明原因，不要无必要引入重量级依赖。**
- 持久化位置按 Windows 用户数据目录：如 `%LOCALAPPDATA%\YeImageViewer\...`，实际路径依照项目已用的 app data 策略，不能硬编码 `C:\Users\color`。
- 维护独立 `schemaVersion`，今后增加字段能无损迁移；损坏时先备份、提示并尝试恢复，而不是静默清空。
- 写入在 UI 线程外或采用可靠的小型同步方案，但退出时确保已提交记录落盘；写入失败有可见错误提示、不会毁掉原文件。
- 默认**不保存屏幕截图原图、窗口标题、进程名、网络内容、图片完整路径**。坐标与显示器信息支持“保存 / 不保存”设置，建议默认仅保存颜色、时间、来源和简要坐标，允许用户关掉坐标持久化。
- 可以导出 JSON/CSV（P2），导入时对版本、字段、色值范围、条数、重复 ID 做校验；避免任意路径覆盖与恶意过大输入。
- 收藏是与历史不同的逻辑表/文件：收藏可以改名、分组、固定，清历史不应删除收藏。
- 完全离线运行，不产生颜色数据的网络请求。

## 8. 模块架构、接口和事件约定

先审查 YeImageViewer 的实际语言与 UI 框架。下列模块名只是建议，允许等价实现：

```text
YeImageViewer (existing)
  ├─ Toolbar/Menu/Hotkey → ColorFeatureController
  ├─ existing Theme / Settings / Logger / Build
  │
  └─ ColorFeature
       ├─ ScreenCaptureBackend (IScreenSampler)
       ├─ DisplayGeometry / DpiCoordinateMapper
       ├─ PickerSession + PickerOverlay (HUD)
       ├─ ColorValue + ColorConvert (pure functions)
       ├─ ColorWorkbench (P1a)
       ├─ HistoryRepository (P0 minimal, P1b full)
       ├─ ColorFavoritesRepository (P2)
       └─ ColorPalettes / ImageColorSampler (P2)
```

### 8.1 最小核心数据契约（伪结构，按实际语言落地）

```text
RGBA8 {
  r: uint8, g: uint8, b: uint8, a: uint8
}

ScreenPoint {
  physicalDesktopX: int,
  physicalDesktopY: int,
  monitorId: string,
  monitorPhysicalBounds: Rect,
  monitorRelativeX: int,
  monitorRelativeY: int
}

PickedColor {
  color: RGBA8,
  space: "captured-screen-SDR" | "decoded-image" | ...,
  source: "screen" | "image" | "adjustment",
  point: ScreenPoint?,
  capturedAt: timestamp,
  sessionId: string
}

CommitResult {
  clipboardSucceeded: bool,
  historySucceeded: bool,
  historyRecordId?: string,
  error?: message
}
```

**接口语义：**

- `IScreenSampler.Capture(displayTopology)` 得到**可审计像素缓冲/错误类型**，不返回 GUI/鼠标事件。
- `ScreenGeometry` 负责显示器物理边界、鼠标物理坐标、当前显示器相对坐标和 HUD 位置；所有坐标变换集中定义和测试。
- `ColorMath` 保持纯函数：输入规范 RGBA、输出不同颜色模型；不要把颜色计算散落在输入框的事件回调中。
- `HistoryRepository.AppendCommitted(...)` 只能由**确认提交事件**调用，不能由 `mouseMove`、`previewChanged` 或控件渲染调用。
- `PickerSession` 负责单例会话、焦点/鼠标/键盘占用、热键注册、取消、异常释放；所有退出路径走统一 `Cleanup()`。
- `ColorWorkbench` 负责当前临时编辑值、Undo/Redo 与 Apply/Cancel；编辑会话本身不等于历史持久化。

### 8.2 非功能性验收指标（目标值，需要真实机器测）

- 目标：常见 1080p SDR 单屏，从快捷键/点击到 HUD 可用约 **300ms 内**；双 4K / RDP 可放宽并记录实测，不允许靠减少正确性来达标。
- 连续取色 50 次，不出现未释放的 overlay、句柄数量不断上涨或系统级鼠标键盘卡住。
- 取色浮层在高 DPI + 多屏移动时不卡顿、不闪烁、不采到自身；鼠标定位误差严格 **0 物理像素**（已知 SDR 色块测试）。
- 非取色状态不执行截图，不持续占用图形采集资源；离线可用。
- 色轮拖动连续操作不应阻塞主界面；历史 500～2000 条可流畅滚动。
- 无强制在线授权/AI；调色、复制和历史在无网络下全部正常。

> 性能数值是**目标而非已测结果**，测试报告必须填写硬件、屏幕布局、测量方式、样本量和实际数据。

## 13. 不做什么 / 需要明确防止的错误

1. **不要**把“屏幕取色”限定在 YeImageViewer 图片区域。
2. **不要**把已编译 uTools 运行包当成允许复制的 YeImageViewer 原生源码。
3. **不要**引入 Electron/uTools 仅为了调用 `screenColorPick`。
4. **不要**用屏幕上的放大后的格子反向推断原像素，不要采样自己的 HUD。
5. **不要**把“虚拟桌面绝对坐标”错误地按 `(0,0)` 非负处理。
6. **不要**把“显示器相对坐标”当成当前应用窗口坐标。
7. **不要**让鼠标移动每帧生成历史，导致成千上万条垃圾数据。
8. **不要**将历史仅保存在最近六个颜色的内存数组中。
9. **不要**让“调整”未确认时覆盖取样原色和历史原记录。
10. **不要**把 CMYK / LAB / HSI 的近似转换当成专业 ICC 印前测量。
11. **不要**默认开启全局热键、常驻截屏、网络上传、AI 请求。
12. **不要**因为追求复杂色卡、AI 或炫酷 UI，拖延前三个核心功能。
13. **不要**为了截图而绕过系统安全桌面、防截屏和 DRM 机制。
14. **不要**忽视鼠标右键退出等旧行为：取色会话结束后事件与设置应恢复。
15. **不要**只报“已完成”却没有编译、运行、测试和缺陷证据。

## 15. 完成标准总览（可直接勾选）

### P0 — 全屏快捷取色

- [ ] 在其他普通软件窗口上获取像素；不是只在图片内取色。
- [ ] 多屏负坐标和显示器相对坐标正确；P 一键切换。
- [ ] 15×9 放大镜中心采样像素准确；四个角 HUD 不越界。
- [ ] HEX / RGB / HSL / HSV 格式切换、复制内容正确。
- [ ] 点击/Enter 确认、C 复制、Esc/右键取消、安全释放资源。
- [ ] 取色后有简洁提示，可一键“调整”“历史”“再取一次”。
- [ ] 全局快捷键可选且默认关闭；与旧软件快捷键无冲突。
- [ ] 通过可用环境内的 CP 测试，并对不可测试场景如实标 BLOCKED。

### P1a — 颜色调整

- [ ] 色轮/滑块、HEX/RGB/HSL/HSV 可双向联动修改。
- [ ] 原色/新色同时显示；撤销/重做/重置/取消/应用有效。
- [ ] 各种格式单独复制；非法输入安全；颜色转换精度经单测。
- [ ] 调整中不写历史，仅“应用”生成一次新记录。

### P1b — 历史

- [ ] 取色和调整历史真实落盘，重启仍在。
- [ ] 时间倒序、颜色预览、复制、再编辑、搜索、删除、清空。
- [ ] 重复提交规则明确；鼠标移动绝不污染历史。
- [ ] 数据上限、存储损坏恢复、隐私设置、安全写入有测试。
- [ ] 收藏与历史独立；清空历史不影响收藏。

### 后续扩展

- [ ] P2 UI 色卡、传统色、渐变、图片提色等在前三项稳定后独立迭代。
- [ ] P3 AI 配色维持非必需、默认不启用，用户确认后再规划。

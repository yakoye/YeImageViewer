# 取色历史 / 收藏 / 数据存储契约

## 数据源和保存时机

| 操作 | 是否入历史 | 是否影响收藏 |
|---|---|---|
| HUD移动/冻结/移动准星/颜色候选 | 否 | 否 |
| Esc/右键取消取色 | 否 | 否 |
| HUD C复制（单纯复制） | 默认否，用户可改为“复制即记录” | 否 |
| HUD左键或Enter确认 | 是，每个会话动作一次 | 否 |
| 从颜色编辑器点击应用 | 是，记录parentRecordId | 否 |
| 连续拖色轮/拖滑块但没有应用 | 否 | 否 |
| 历史复制/删除/搜索 | 不添加 | 否 |
| 点击收藏或“将方案添加收藏” | 不添加，除非明确触发“应用” | 是 |

> 与v1.1的“复制可能记录”和v1.0的“确认记录”兼容：此处明确**默认只将已确认取色与应用后的调色写入历史**，用户可单独启用复制即记录；同一次逻辑事件有会话唯一key避免双份历史。

## 推荐Schema（只给示意，按现有项目实现）

```json
{
  "schemaVersion": 2,
  "records": [
    {
      "id": "uuid-or-monotonic-id",
      "sourceType": "screen",
      "timestampUtc": "2026-10-20T01:23:45.123Z",
      "rgba": [83,202,164,255],
      "coordinate": {"space":"screenPhysical","x":-100,"y":350,"monitorId":"stable-or-session-local"},
      "parentRecordId": null,
      "eventKey": "picker-session-action-id",
      "label": "",
      "tags": []
    }
  ]
}
```

- 颜色源以RGBA整数通道存储，HEX/HSL/Lab均为即时派生展示，不应持久化数个互相矛盾的主副颜色表示。
- 屏幕物理坐标有隐私选项：默认“只保存颜色/时间/来源”最小化；如果用户开启，记录坐标和模式，关掉后新记录不存坐标，不尝试精确定位旧物理显示器。
- 不保存原屏截图、进程名、窗口标题、整图字节；错误日志不写色彩之外的个人敏感内容；AI网络流量需显式用户同意。
- 历史数据与收藏独立表/文件。清历史不清收藏；撤销删除与事务可靠性对齐存储方式。

## 存储操作与损坏恢复

- 文件路径依据既有项目settings规范，缺省用户LocalAppData，不固定用户名。推荐JSON版控与原子替换(temp -> fsync or equivalent -> replace)，保留上一个有效备份；也可以采用既有SQLite事务方式。
- 操作必须校验：schema版本、颜色范围、time格式、重复ID、parentId、坐标mode及可能空值、最大入站文件尺寸。旧版增量迁移不可丢用户设置/收藏。
- 多窗口/多进程执行写入：单写者或锁/事务策略，禁止互相覆盖；文件权限/磁盘不足明确失败，不能默默把历史标记保存成功。
- 搜索/筛选/分页：最近优先，精确HEX、日期范围、来源、命名、标签；5000条能滚动；导入/导出JSON/CSV保留元数据。
- 保留上限默认1000，可选100/500/1000/5000/无限；同色不同时间作为独立事件，重复动作防重提交。

## 收藏与渐变结构

收藏类型为 `color / gradient / palette`，至少包含id/name/tags/notes/createdAt/updatedAt/order/type/payload。`gradient`保留角度、径向属性、色标与位置、插值模式、alpha；`palette`保留多个颜色、顺序、角色名及来源。所有类型支持JSON导出/导入、编辑与搜索。

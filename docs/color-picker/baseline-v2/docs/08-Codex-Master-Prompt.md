# Codex 开发总指令（完整范围，不允许只做P0～P1）

你现在负责在现有 YeImageViewer Windows 工程中实现完整的 Color Picker + Color Assistant。请先阅读本包 README 和 `docs/01-Full-PRD.md` 至 `docs/07-Implementation-Roadmap.md` 以及 `docs/11-Reference-Review.md`，并核对七张截图。

## 唯一最高优先级的范围约束

**所有讨论过的功能都需要开发！** 用户只要求先做三件事：
1. P0 全屏快捷取色：图1，任何普通桌面软件区域、多显示器、边界与混合DPI；
2. P1a 取色后颜色调整（包含图片原始像素取色）：图2/3全部字段、色轮和推荐配色；
3. P1b 取色历史：能跨重启保存、搜索、复制、回编辑、管理/导入导出。

然后必须继续：P2 UI色卡/图片色卡/传统色/渐变/收藏和对应完整交互；P3 离线智能配色；P4 AI自然语言配色排最后（若用户后续明确要求删除才从范围变更，不能擅自删）。**先做不等于后面不做。**

## 必须执行的工作流程

1. 先审计当前YeImageViewer源码，确认技术栈、ToolBar/右键/热键/DPI/图片解码、主题、数据目录、Build脚本，并在 `docs/color-picker/Audit.md` 保存真实结论和兼容风险；不得假装已经读过不存在的文件。
2. 拆分小里程碑，每阶段在可编译代码基础上实现真实功能，设计独立颜色数学、屏幕采样、HUD、源图像素采样、助手页面、历史数据。优先复用既有框架，避免新增大型运行时。
3. **测试不得缩水**：保留原本 CP-001～CP-100 的100条、执行本包正式计划中的额外用例，总计 **259个唯一测试用例**。原v1.1共81条在archive另保留，交叉核对而不是覆盖100条。对于环境无法运行的用例写BLOCKED并记条件。
4. 每新增功能先建立/更新case，算法单测先于UI或随UI提交；每修复缺陷补回归。发布前运行实际可运行的测试并记录真实命令、结果、日志、设备环境；禁止把未运行填PASS。
5. 每个阶段更新README/设计/实现日志/测试设计与实测报告/Issue或BugTracker/CHANGELOG/ReleaseChecklist/RequirementTraceability。
6. 第三方uTools颜色助手5.0.1是打包参考插件，**没有确认可复用许可证**。只借鉴行为/信息架构/通用算法名称；不能直接复制压缩后的JS、CSS、图标、专有色卡数据或集成utools.screenColorPick，必须适配本项目原生Windows API实现。
7. 原图片浏览器必须零重大回归：缩放、拖拽倍率、Shift精细拖拽、右键配置、图片切换、大图、GIF、旋转/镜像、工具栏布局和原有快捷键。
8. 每次阶段交付列出：修改的文件、版本、构建步骤与真实结果、已执行测试ID/结果、未执行/阻塞项、功能完成清单、下一阶段计划。不要在P1结束时声称全功能已经完成。

## 推荐第一轮交付

只先执行审计 + P0，实现一个确实可用的多屏取色HUD，给出包含真机构建/测试证据的RC包，继续后续阶段直到本包范围全实现。若项目仓库未提供或存在不可访问文件，应先明确提出需要仓库，不得杜撰修改。

## 完成定义

- 最终图1～7对应的每一项可交互功能、历史新增页、离线配色和AI最后阶段均真正实现或经用户签字确认删除需求。
- 259个正式测试ID均有结果与证据；符合条件的自动/人工测试通过，BLOCKED项有范围说明，不存在谎报通过。
- 打包的源码、脚本、文档、测试、资源（色库经许可审核）在干净环境能构建，发布记录齐全。

# 可直接交给 Codex 的分阶段开发指令

你正在维护 Windows 图片查看器 **YeImageViewer**。本次要实现取色器与颜色助手。先阅读当前代码仓库、`README`、`docs/`、`CHANGELOG`、构建脚本，以及随同提供的：

## 执行原则

1. **先审计，后开发**。梳理 GUI 技术栈、图像解码/像素接口、DPI/多显示器/主题、菜单与工具栏、快捷键、窗口生命周期、测试框架、`build.bat`。不要推倒现有架构，不做无关代码重构。缺少源码时停止并明确请求源码，不要伪称已完成实现。
2. 按现有项目的版本规范实施。未验收通过一律用合适的 `rc` 修复号，不应跨版本宣告 stable。不要自行随意指定软件“最新版”。
3. 每个功能都要对照需求 ID / 测试 ID 设计和实现；**每修复一个缺陷补一条回归测试**。
4. 自动化与测试报告严格区分：编译通过≠运行通过，未实测必须写 `NOT_RUN`，真实环境受限明确写 `BLOCKED`。
5. 避免额外依赖，优先集成 YeImageViewer 的既有 GUI、主题、设置、色彩与图像组件。设计采样接口以便 Windows GDI / DXGI 后端可切换。
6. 除非用户另有决定，**第一阶段只做 P0：可靠全屏取色**；保留后续颜色助手可扩展接口，不要一次塞进 AI 云服务或一大套未验收色库。
7. 任何按键变更必须审查 YeImageViewer 当前快捷键映射，避免覆盖 Shift 精细拖动等功能；全局热键必须由用户显式开启。
8. 取色必须覆盖桌面**任意普通软件及所有显示器**，不能局限 YeImageViewer 图片窗口；图片原始像素取色是独立模式，留待 P1。
9. 不复制第三方应用版权代码、品牌资产或未经授权的传统色数据。

## 步骤 A — 输出代码审计与分解计划

请先给出：

- 现有程序的实际文件/模块路径和技术栈（以 repo 事实为准）；
- 工具栏吸管入口应加入哪里、图标如何复用统一规格；
- 现有图片显示与坐标变换机制；
- 现有主题、快捷键和配置存储机制；
- ScreenSampler 和 HUD 与 Viewer 的边界；
- P0 修改文件清单、可能破坏原功能的风险和规避方法；
- 需要新建/更新的 docs 文件列表；
- 编译和测试方法。

在不依赖用户做架构决定的情况下，选择**改动最小、可验证、便于后续扩展**的方案，然后继续实现。

## 步骤 B — 实现 P0 屏幕取色器

实现：

1. YeImageViewer 工具栏与菜单的取色入口；紧凑顶层 HUD；用户可随时 ESC/右键取消。
2. 在 HWND/GUI overlay 出现**之前**先采集全部显示器的桌面内容；任意屏幕位置可取样；正常情况下提供实时刷新，若排除 HUD 采样失败则明确采用快照回退模式，绝不能采到 HUD 自己的颜色。
3. 15×15 像素放大网格，中心十字；倍率设置、HUD 跟随、屏幕边界上下左右自适应。
4. 使用 Windows 物理像素坐标，P 切换屏幕绝对和所在显示器相对，支持负坐标；不要把 125%/150% 等 DIP 当物理像素。
5. HEX/RGB/HSL/HSV 格式，Shift 循环切换、C/CTRL+C 复制、左键确认、ESC/右键取消、Space 冻结/解除、方向键移样本。
6. 左键确认的默认行为“复制+退出”；可在设置中改为“复制后继续”“选择后打开助手”（后者 P0 可以仅预留配置，未实现则不可提供虚假的可点击选项）。
7. 清晰区分复制成功与复制失败；采样失败不得复制上一色冒充当前色。
8. 多屏、混合 DPI、热插拔、RDP 失效清理；异常不留顶层遮挡窗口、指针 capture 或已注册热键。
9. 用户设置/主题/帮助文字；默认全局热键关闭；不改变任何图片查看器原交互。

### P0 必过验证

- `#53CAA4` 的 R=83/G=202/B=164 等校验向量；标准黑白红绿蓝样本。
- 双屏第二屏取色，第二屏置左负 X、置上负 Y，双屏不同 DPI。
- 光标靠近四角时 HUD 完整可读，十字与真实采样像素一致。
- 快捷键 P / Shift / C / Esc / Space 在激活/退出模式前后作用范围正确。
- 多次进入/退出/异常关闭，不会残留顶层透明窗口。
- 原 YeImageViewer 图片浏览/拖拽/缩放/切换/全屏功能不退化。

## 步骤 C — P0 真实构建与文档更新

- 运行项目真实 `build.bat`（或 repo 现有构建流程），检查构建输出和 exe；不要仅静态宣称“可编译”。
- 运行已有自动化测试 + 新增 `ColorMath`、`CoordinateMapper`、`PickerStateMachine` 测试；把命令和通过/失败数量写入实测报告。
- 如工具执行环境无 GUI/多显示器，手动多屏测试明确标记 `NOT_RUN` 并附用户在 Windows 上的复测操作，不得写 `PASS`。
- `docs/` 维护需求、设计、测试设计、测试实测、缺陷追踪、CHANGELOG、版本 roadmap、发布 checklist；同步更新 README 的用户快捷键文档。
- 所有新增资源随 exe 正确打包，图片与 JSON 不丢失。
- 最终交付完整代码补丁/文件及实际编译产物，说明可覆盖目录、构建步骤、版本号、已验证项、未验证项和已知限制。

## 步骤 D — P1 ～ P3（P0 真正通过后进行）

- **P1**：图片原始像素 RGBA、反向坐标映射、色轮工作台、HEX/RGB/HSV/HSL/CMYK/HSI/LAB 双向联动、离线推荐配色、历史与收藏。
- **P2**：UI 色库、合法来源的传统色、中国节气分组、日本传统色、渐变与 CSS 导出、当前图片提色、收藏导入导出。
- **P3**：WCAG 对比度、完整离线主题配色、AI 接口可选且须显式授权、HDR/ICC 精度增强。

**本轮请从审计和 P0 开始，完成并验证以后再进入下一阶段。** 不能用“架构已经设计”代替真实的功能实现。

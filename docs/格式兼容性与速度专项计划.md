# 格式兼容性与速度专项计划

日期：2026-10-15。用户要求本版本重点解决图片打开慢、打不开、预览后闪错和同类兼容问题。原 v1.38.2 公开发布暂停，未推送、未创建 Release；已生成正式包不能视为本专项完成后的交付。

## 实施顺序

1. 保存六份真实问题文件的路径、尺寸、文件头和 SHA-256；对当前构建运行有超时的独立解码探针，建立成功／失败／崩溃／像素／耗时基线。原素材不修改、不上传。
2. 按真实容器而非后缀确认文件格式；结合独立解码器核对尺寸、透明度、颜色与内嵌预览。区分文件截断、格式不支持、错误成功和正常但缓慢的解码。
3. 研究 PhotoCraft／LightCraft 的格式识别、RAW／PSD／TIFF 解码与预览策略，记录版本／许可；可借鉴机制，不未经核验引入整个依赖栈。必要时替换或新增解码后端，由兼容性、性能、包体、许可证和可测试性共同决定。
4. 修复整条同类路径：格式嗅探与分派、PSD／PSB 合成图与压缩模式、TIFF／CMYK／多页、RAW 验证与内嵌预览、渐进加载替换规则。范围以实际复现为依据，不用文件名或特定尺寸打补丁。
5. 用最小无隐私夹具覆盖每项缺陷，新增正确像素／透明度／异常数据／超时回归；扩展相关位深、色彩模式、压缩、后缀不一致组合，并同步主程序／缩略图／格式列表。
6. 与本机 GuoheView 比较同一素材、相同进程启动方式、多个轮次中位数；首个可用画面与最终完整画面分开，不把预览速度当完整解码速度。官方宣称、实际打开、正确出图三个层次分别记录；不同功能和插件配置明确列出。
7. 修改后运行完整 `runTests.ps1`，专项解码和真实窗口冒烟分别报告。未通过、不具备桌面条件、缺少对比软件或样本的项目明确标注，不伪报全面支持。
8. 专项完成后重新确定交付构建，沿用绿色 EXE／ZIP／7z、校验清单及本地／NAS 项目版本归档。此前发布授权不意味着允许在专项未完成时发布旧包。

## 验收要求

- 六份文件逐一给出原因、修复状态、正确出图证据和修复前后耗时；损坏或仅可预览的文件明确说明，不把错误图或低清预览标作完整解码成功。
- 同类夹具能在修复前失败、修复后通过；透明、色彩、尺寸、帧／页等不能仅用“不崩溃”替代验证。
- GuoheView 对比明确软件版本、插件、机器、轮次、缓存和测量口径；不宣称无法证明的冷盘速度或格式全面领先。
- 无高频渲染阻塞 I/O，无无限兜底解码，无覆盖用户配置、原图或历史包。

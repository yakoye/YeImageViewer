# PhotoCraft 图层后端移植与对齐计划

日期：2026-10-22。用户已确认以 PhotoCraft 代码为实现来源，同时对齐 Photoshop 风格的界面、操作、分组、蒙版、混合与显隐。**不是只换标题或画一个类似列表。最终目标尚未完成。**

## ADR：接入原引擎，不继续扩张受限的8位RGB合成器

决定：保留 C++/Win32 看图、默认原始合成图与现有设置；通过最薄 C ABI 直接链接固定版本 PhotoCraft Rust `io/doc/compose`，只在打开图层会话时加载。

备选方案是继续翻写每个算法，优点是无需工具链与DLL；但复杂蒙版、效果、调整及模式已经超出旧实现，并且难以保证与参考软件一致，因此不作为本次完整对齐路线。整套移植 egui 编辑器会扩大界面和依赖，不符合就地轻面板。

上游 `9b18f57344ff70d6f5aa640a0db7bc55596d5324`，MIT许可；品牌资源不移植。公开原PSD导入函数的一行可复现补丁，不改其算法。实际构建比较：仅格式映射约5MiB但漏掉完整导入处理；通用导入入口约20MiB；保留原PSD入口约11.3MiB。仍保留主EXE的28MiB门槛，不因新增后端取消体积检查。

- [x] 多层显隐直接使用原文档树重新合成；CMYK不再因旧RGB限制统一禁用。

- [x] 像素蒙版缩略图；Shift点击启停，Alt点击查看灰度；分组展开跟随真实层级，Alt展开/折叠全部组。

- [x] 默认原始状态仍显示保存合成；有可测差异时提示，不静默认定“忠实重建”。

## 后续必须继续，不能拿第一批专项代替

1. **复杂CMYK同状态核对。** `43.psd` 与保存画面差异明显；独立PhotoCraft合成图读取器也读到相同的保存画面，不能简单归因于本项目默认解码错误。需要与参考软件/Photoshop同状态核对，区分渲染语义差异与过期合成缓存，再针对可最小化问题修正。`42.psb` 也不宣称像素完全相同。
2. **面板继续对齐。** 类别筛选、图层多选/范围选择、键盘移动焦点、与PS一致的眼睛隔离/恢复、原生通道多眼睛组合及叠加、数值直接输入/拖动、图层/通道的完整右键操作和更细致视觉布局仍需补齐。不得把当前单选面板称为完整PS面板。
3. **复杂特性矩阵。** 分组混合、剪贴链、密度/羽化、矢量蒙版、特殊Fill、Blend If、调整/效果/智能对象的正确率要按独立样本登记；链接了上游实现不等于本项目已逐项验收。
4. **性能及异常。** 多次切图/取消/关闭、缓存资源、冷启动/热切换、Win10 4K200%、本地与RDP、多屏ICC分别检查；不能用模拟DPI等同实机。

不增加原PSD写回接口；浏览变化只在当前会话生效。后续如支持编辑文档或原格式保存，应单独明确功能和安全边界。

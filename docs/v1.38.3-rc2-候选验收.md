# v1.38.3-rc2 候选验收

日期：2026-10-18。延续 rc1 的功能与边界，只交付候选绿色包，不公开发布。

## 本轮缺陷与原因

取色面板收到 `WM_DPICHANGED` 后销毁所有子控件并重新创建，`updateFields()` 会把未完成输入重置为上一个有效颜色，原有选区、焦点及复制按钮校验状态也会丢失。仅把控件放在新客户区内，不能证明输入状态正确。

修复改为保留原控件，只更新其位置、尺寸和字体。RGB 标签有独立控件 ID；旧字体在所有子控件切换到新字体之后释放。DPI 更新不再调用初始化色值逻辑。

## 修复前证据

`artifacts/image-tools-rc2-before-build.log` 构建含新增回归但未修复的版本；隔离目录运行 `scripts/test-image-tools.ps1`，退出 1，生产自检退出 2。

`artifacts/image-tools-rc2-before.log`：`picker=0`、`layers=1`、`dpi-preserved=0`，同一轮桌面已知色块仍正确（BGR=239,171,18）。失败不是把取色环境异常当作本次缺陷复现。

测试将 HEX 输入停在 `#12`、RGB 绿色输入停在非法值 `999`，设置文字选区，再依次通知 192、288、96 及初始 DPI，检查控件身份、两份原始输入、选区、上次有效颜色及两个复制按钮的禁用状态。

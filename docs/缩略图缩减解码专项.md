# 缩略图缩减解码专项

日期：2026-10-17。当前为后续开发代码，未替换 v1.38.2 公开包，未生成或归档新的正式版本。

## 问题与实现

标准 COM 接口只请求 256 像素，但旧 WIC 路径会先生成整张 BGRA，随后最近邻缩小。8192×4096 的无用户内容夹具上，峰值提交增加约 129 MiB。旧缩略图路径还会忽略 CMYK ICC；细密纹理用最近邻缩小出现强烈混叠。

本次仅修改缩略图组件，不将其性能数据冒充主窗口打开速度：

1. 将目标边长传给 WIC 路径，在解码链中完成缩小。RGB 等格式让 scaler 紧跟 frame；微软文档说明这能利用支持该功能的 codec 的原生变换，见 [IWICBitmapSourceTransform](https://learn.microsoft.com/en-us/windows/win32/api/wincodec/nn-wincodec-iwicbitmapsourcetransform)。没有原生缩减的 codec 仍可能内部完整解码，不宣称所有格式都达到相同内存上限。
2. CMYK 不走隐式 BGRA 转换：先保留原生墨量和嵌入 ICC，复用 `CmykColor` 转 sRGB。JPEG 原生缩减可用时先缩减墨量；不可用时完整解码兜底。
3. 最终目标矩形始终由原图宽高计算，防止 IDCT 各边取整后出现 256×170 变成 256×171。
4. CMYK 完整解码兜底也在色彩转换后做面积缩小，不能重新落回最近邻，避免细密海报纹理变成白点。第三方 codec 的缩放链失败时仍保留原来的可显示兜底。
5. 不放大小图、不改变主窗口缩放/平移规则，不改 PSD/PSB 和 RAW 的既有格式判断及解码顺序。

## 新增自动化闸门

`runTests.ps1` 已登记 `scripts/test-thumbnail-scaling.ps1`，逐例使用测试程序的独立子进程调用真实 DLL，不经过注册表或 Explorer 缓存。源文件和参考 PNG 均在 `test/thumbnail-scaling`，生成方法与授权来源见该目录 README。

| 用例 | 关键断言 |
| --- | --- |
| 33 MP RGB JPEG | 最终 256×128；新增峰值提交≤64 MiB；参考像素正确 |
| 33 MP 无 ICC CMYK JPEG | 原生缩减后墨量/K/通道与独立参考一致；同样有内存约束 |
| 33 MP 带合成 ICC CMYK JPEG | 非恒等 ICC 必须真正参与转换；不能忽略后仍报告通过 |
| 非整除尺寸 CMYK JPEG | 3543×2362 必须输出 256×170，不被 IDCT 舍入改变比例 |
| 透明极长 PNG | 8×4096 → 1×256，尺寸不退化为 0、透明与预乘正确 |
| 小 PNG | 5×3 保持原尺寸，不放大 |
| 16 位 CMYK TIFF | 原生缩减不可用时颜色正确，兜底仍可显示 |
| 密纹 CMYK TIFF | 黑白点缩小应为灰，不能采样为纯黑/纯白 |

尺寸、成功状态和实际输出像素必须同时通过。参考图由 ImageMagick 独立解码；有 ICC 时明确转换到合成的标准 sRGB profile。平均通道误差≤4、最大≤32；不使用容易受负载影响的毫秒阈值作为通过标准。

### 本次复验发现并修正的测试问题

1. 旧完整入口部分窗口直接运行开发目录EXE，会读写旧DB。新增 `scripts/New-RegressionRuntime.ps1`，完整入口改用本轮独立运行目录，只复制EXE/DLL、不复制DB。`scripts/test-regression-runtime.ps1` 验证副本哈希、拒绝旧运行路径、目录互相独立和源配置不变。失败目录保留供诊断，不丢失配置证据。
2. 旧Esc录制只 `SendMessage(WM_KEYDOWN)`，但设置页正确地使用 `GetKeyState` 读取目标输入队列状态。实际失败DB中的绑定为65563，即Ctrl+Esc，不是27。新诊断在未主动注入按键的那一轮还捕获到异步Ctrl状态为按下。Windows这两种输入状态的区别见 [GetKeyState文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getkeystate)。
3. 修正的是测试输入，不是产品录制规则：测试先取得自己设置窗口的前台，在该窗口同步修饰键松开事件，确认状态清空且前台未变化，再发送成对Esc按下/松开；保存后额外检查实际绑定必须为27。`scripts/test-shortcut-recording.ps1` 主动在自己的设置窗口注入Ctrl按下，复用完整入口同一函数，确认录回Esc、关闭图片、源DB哈希不变；无论成功失败都释放自己注入的键。

上述两个新测试均登记进完整入口。最终日志中的一次“检测到Ctrl按下”来自新回归主动注入，不能据此声称又发生了外部输入干扰。产品交互代码没有为这次测试作额外改动。

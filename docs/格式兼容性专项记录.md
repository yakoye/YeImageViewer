# 格式兼容性专项记录

日期：2026-10-16。状态：开发与验证中，尚未重新公开发布。用户素材不修改、不上传；原 v1.38.2 正式包仅为本专项开始前产物，不作为本专项交付。

## 原因与实现

| 问题 | 原因与处理 |
| --- | --- |
| `42.psb`／`43.psd` 无法打开 | 两者为 CMYK；旧 psd_sdk 仅接受 RGB，且缺少 PSB 分派。用共享合成图解码器替换主程序与缩略图的旧路径，直接读最终合成图；支持 PSB 长度、RLE 行表、ZIP／连续 ZIP、预测、色彩模式与透明标记；不展开图层，不伪称重建未保存的合成结果。 |
| 日期命名的 JPG 先显示再错误 | 实际是 Nikon Z f 高效率 RAW。按容器纠正分派，LibRaw 成功码还须通过数据错误计数检查；不支持／错误时选最大有效内嵌 JPEG。界面和元数据明确标记预览，保留 JPEG 的 ICC 和方向，不把它叫作 RAW 原始成像。 |
| TIFF 打开约四秒 | 大型 Photoshop 二进制元数据被 `toString()` 展开成巨大数字串。先按 64 KiB 单项预算判断，再决定格式化；保留键名与字节数说明。五轮独立进程总耗时中位数 4166 → 218 ms。 |
| CMYK JPEG／TIFF 色彩 | 不能把墨量通道当 RGB，也不能丢掉 K。读取 WIC 原生 CMYK 并通过嵌入 ICC 转到 sRGB，后续不重复套原 CMYK profile；无可用 profile 才用明确的基础转换。 |

曾尝试直接调用仓库现有 TurboJPEG API 加速 CMYK JPEG，但出现 RAW 回归，已撤回；不将尚未证明兼容的静态库混用放入交付。当前大 CMYK JPEG 完整转换比旧简化算法耗时更长，不宣称全面提速。

## 参考项目与取舍

- [LightCraft 合成图实现](https://github.com/storytold/lightcraft/blob/0da998f24dfc03069d49867f8877af2bf7c51f94/crates/codecs/src/psd.rs)：借鉴“查看器优先读取已保存合成图”、严格长度边界和透明标记的设计。C++ 代码按 [Adobe PSD／PSB 公开规范](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/) 独立实现，没有把整个 Rust 应用移植进来。
- [LightCraft RAW 预览说明](https://github.com/storytold/lightcraft/blob/0da998f24dfc03069d49867f8877af2bf7c51f94/docs/user/troubleshooting/preview-only-raw.md)：区分预览可用与 RAW 变体真正可解码；Nikon 高效率 RAW 也在该项目的预览示例范围。没有据此宣称其能解出本素材的传感器数据。
- [LightCraft 预览读取设计](https://github.com/storytold/lightcraft/blob/0da998f24dfc03069d49867f8877af2bf7c51f94/docs/raw-preview-reads.md)：关注预览读取范围、方向／色彩保留与失败退路。当前项目已用只读映射，不照搬整文件稀疏缓冲和编辑器缓存体系；更深入的视口／瓦片加载不是本轮已完成能力。
- [PhotoCraft 格式文档](https://github.com/storytold/photocraft/blob/df055f3dcb0bb0312af97548ee6c6f9628f21dd7/book/src/formats/psd-psb.md) 与 [解码器依赖](https://github.com/storytold/photocraft/blob/df055f3dcb0bb0312af97548ee6c6f9628f21dd7/crates/codecs/Cargo.toml)：借鉴真实语料、位深／元数据保持与独立参考解码验证，不直接引入完整图层编辑／导出或整套依赖。两项目仓库元数据标识 Apache-2.0，同时提供 MIT／Apache 许可文件；本轮未复制其 Rust 源码。

## GuoheView 格式对照基准

本机安装版版本为 3.4.8.116，`plugins/decoder` 只有说明文件，没有解码插件。[官方格式页](https://pic.ghxi.com/en/docs/formats) 与 [插件说明](https://pic.ghxi.com/en/docs/plugins) 是宣称范围，不等同本机所有变体实测通过。

| 范围 | 本项目当前情况 | GuoheView 文档／本机配置 |
| --- | --- | --- |
| 常见栅格／动图 | 原有解码与动图语料保留 | 文档列为内置 |
| HEIC／AVIF／WebP | 内置，有既有语料 | 文档列为内置 |
| JPEG XL | 内置，有静／动图语料 | 文档要求插件；本机未装 |
| PSD／PSB | 本轮新增 PSB 与 CMYK 合成图，做位深／压缩／像素矩阵 | 文档支持已保存的合成结果；原文件实测另记 |
| TIFF／CMYK | 保留多页，新增 8／16 位原生 CMYK 路径与元数据性能修复；七个压缩／位深／多页夹具 | 文档宣称多页、CMYK、瓦片加载；不能据此认定本机所有文件正确 |
| RAW | 扩展名列表不代表每个压缩变体可完整解码；内嵌预览必须单列 | 文档列多厂商 RAW，同样需要实际变体测试 |
| SVGZ、AI／EPS、EMF／WMF | 当前没有声明完整支持，不冒充此次已新增 | 官方列有支持／预览，属于已知覆盖差距 |

速度对比应在相同文件、硬件、缓存条件和独立负载下重复测量。首个可用画面、完整像素成像与纯解码不是同一指标；公开宣称、实际打开、正确像素分别记录。无法得到 GuoheView 完整解码结束信号时，不用进程建窗或截图自动化耗时冒充它的解码毫秒数。

### 本机真实窗口实测

GuoheView 3.4.8.116 正常显示 `42.jpg`、`42.psb`、`42.tif`、`43.jpg`、`43.psd`，逐张核对最终尺寸与实际画面。原始日期命名 `.jpg` 报无法打开；仅在隔离目录复制同一字节为 `.nef` 后，可显示 4032×6048 的正确画面，不能从界面证明是真 RAW 解码还是内嵌预览。原文件未改。

本项目新版六个原文件均能显示，RAW 不用改后缀，持续标识“RAW 内嵌预览”，数秒后仍保持正确竖图，没有再被错误真解替换。其余五张分别核对最终尺寸与海报实际画面；隔离 EXE／DB，不污染用户配置。

未得到 GuoheView 可验证的“完整解码结束”信号，因此其毫秒数和双方速度倍数仍未完成，不能用自动化截图返回时间代替。官方 [大图说明](https://pic.ghxi.com/en/docs/big-image) 的瓦片／视口加载与本项目完整 CPU 画布路径也不同，不把首个预览与完整解码混比。

## 五轮修复前后基准

`scripts/benchmark-decoding.ps1`，同机、已有文件缓存、独立进程，轮流交换两个构建顺序；每文件各五轮。总耗时包含进程启动／解码／探针输出，不含 GUI／PNG 导出，不是冷盘首帧。

| 文件 | 基线成功 | 基线中位 ms | 新版成功 | 新版中位 ms | 说明 |
| --- | --- | ---: | --- | ---: | --- |
| 日期命名 JPG（实际 RAW） | 0/5 | 144 | 5/5 | 456 | 新版为明确标记的内嵌预览；失败耗时不是旧版速度优势 |
| 42.jpg | 5/5 | 945 | 5/5 | 2115 | 14173×9448 CMYK，新增正确 ICC 转换，较旧简化路径更慢 |
| 42.psb | 0/5 | 50 | 5/5 | 294 | 从无法打开到可显示；不与失败耗时算提速比 |
| 42.tif | 5/5 | 4166 | 5/5 | 218 | 避免把大型图层元数据展开为字符串 |
| 43.jpg | 5/5 | 127 | 5/5 | 219 | CMYK ICC 色彩修复，同样有转换成本 |
| 43.psd | 0/5 | 53 | 5/5 | 296 | 从无法打开到可显示 |

证据为 ignored `artifacts/compatibility-v1382/benchmark` 的全部轮次／中位数 JSON 和 `benchmark.log`。基线 SHA-256 为 `83DC7C125072589EB332B5F003607B5CA87B22BC45184FFEB6124FA36B72D9A4`；本轮工作构建为 `2DAA72FA3D8E0486261F759638503759FA088FA880CEECDAB7BCBA656157B6DE`，最终提交重建的包另行校验，不混称同一二进制。

## 原素材像素核对

五份设计图使用 ImageMagick 7.1.2-30 独立读取完整像素，按嵌入 ICC、perceptual 意图转系统 sRGB，再与探针完整 PNG 比较；归一化 RMSE 为 0.00374～0.00380（约 0.95～0.97 个 8 位级别），不是逐字节相同，但没有通道／黑色／透明错位。60 份最小 PSD／PSB 夹具与独立参考最大通道误差均为 0。

RAW 从原文件只读提取最大的完整 JPEG（6048×4032），依外层 RAW 方向逆时针转 90°后，与本项目 4032×6048 预览完整像素比较，RMSE 为 0。没有以独立解码同一 RAW 传感器数据来验证，也不据此改变“预览”标识。证据为 `original-pixels.log`、`original-pixels/结果.json` 和 `raw-preview-pixels.log`；用户图片与导出像素均留在 ignored artifacts，不进入 Git／公开包。

## 测试边界

完整入口仍为 `runTests.ps1`，新增 `scripts/test-format-compatibility.ps1` 纳入最终闸门。PSD／PSB 独立参考 60 项（包含 12 项透明图）、元数据最小夹具、8／16／32 位预测、截断／CRC／PackBits／内存预算、RAW 错误计数和 CMYK 通道规则均需通过；生产扩展名清单直接用于检查语料覆盖，避免重复硬编码列表自证齐全。

当前日志位于 ignored `artifacts/compatibility-v1382`。1050 项单元／集成及 44 个旧格式语料已在中间构建通过，不能把它们代替后续最终提交的完整闸门。后续新增第 45 个 PSB 语料、两个 COM 缩略图用例及七个 TIFF 用例。最终提交后的完整闸门和包体校验结果单独记录；未完成项不报告通过。GuoheView 的精确速度对比仍属未完成项；实测支持与上述本项目基线速度不受该边界影响。

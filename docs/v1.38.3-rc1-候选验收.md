# v1.38.3-rc1 候选验收

日期：2026-10-18（开发与测试跨日）。只交付本地/NAS 候选绿色包，不公开发布。

## 本轮范围

| 项目 | 实现范围 |
| --- | --- |
| 轻工具入口 | 软件内右键菜单 → 轻工具；不扩充常驻浮动工具栏 |
| 取色 | 冻结虚拟桌面、像素放大镜、点击确认、Esc/右键/失焦取消；HEX/RGB 双向编辑、复制与系统颜色微调 |
| PSD/PSB | 按需打开独立只读列表，切换单层栅格；Unicode 名称、隐藏状态、不透明度、负坐标、8/16/32 位和四种压缩；不重建混合、蒙版、调整层或智能对象效果 |
| 保存副本 | 主动保存当前原始分辨率画面的旋转/镜像结果；8 位 sRGB PNG/JPEG，PNG 保留透明、JPEG 白底；不自动修改原文件，不覆盖任何已有文件 |
| DPI 与布局 | 工具提示及加载标记实测字体宽度；无边框关闭按钮改方形、紧贴角落，修正普通全屏点击条件；分隔线降低 RGB 对比度 |
| 退出沉浸 | 按退出瞬间的实际倍率计算边框窗口，同步 WM_SIZE 不重新套默认缩放；只改变当前图状态，下一张仍应用用户规则 |
| 前批成果 | 包含缩略图缩减解码/CMYK 缩小质量、回归运行目录隔离及真实 Esc 录制测试修正 |

旋转、镜像仍是浏览操作，现有 DB 观看记录照旧。导出只在点击“保存旋转/镜像后的副本…”时执行，不保存窗口背景或工具栏；不保留原始位深、全部元数据、动画、RAW 数据或 PSD 图层。失败写入在独占文件句柄上清理本次半成品，不先释放句柄再按路径删除。

取色报告的是桌面显示像素，不承诺 HDR 原始值或图片未色彩管理的源像素。PSD 默认合成图/缩略图路径没有替换，单层解析有数量/名称/解压预算限制，仅解码所选层，不一次展开所有图层。

## 验证记录

- `test/image-tools/` 保存了 24 个小型 PSD/PSB、双层 PSD 和非对称透明 PNG，全部为合成无隐私素材。
- `YeImageViewerTests/ImageToolsTests.h` 验证色值、方向/镜像、透明合成、拒绝覆盖、失败清理、DPI 布局、PSD 单层压缩及多层不同像素。
- `scripts/test-image-tools.ps1` 调用与菜单相同的生产导出任务，16 组组合与独立 GDI+ 逐像素对比；测试源文件和已有副本未变、错误解码无落盘、SVG 平面导出。
- 原生自检创建真实 HEX/RGB 控件与图层列表，验证双向输入、非法值和选择第二层；桌面快照只核对自己的已知色块，不移动鼠标、不保存桌面内容。
- 普通全屏角落关闭测试针对自己的真实进程发客户区消息，旧构建失败记录：`artifacts/image-tools-corner-before.log`；修复后通过。
- 沉浸退出测试验证窗口样式与生产探针中的实际倍率/显示矩形，不只读标题。已用 `test/current image restore/05-tall-capped.svg`（2000×4000）复现：旧构建 0.225494 → 0.755997，修复后 0.225494 → 0.225494。证据为 `image-tools-presentation-before.log` 与 `image-tools-integration-final.log`。原因是启动/切图采用的当前缩放与默认沉浸布局不同，退出时同步 WM_SIZE 又套用默认布局。共享几何策略、源码不变量及故意破坏检查防止再次重算。

最终完整入口日志：`artifacts/image-tools-acceptance-final.log`，退出码 0，以 `All regression tests passed.` 结束：1242 项单元/集成测试零失败、观看窗口专项 80 项零失败、143 个 PNG 快路径逐字节对比、PSD/PSB 正确出图专项 60 项全部通过，其余登记窗口/输入/设置/轻工具回归全部完成。

Release x64 构建记录为 `artifacts/image-tools-acceptance.log`。该轮构建成功，但随后破坏检查写入资源文件时遇到“使用用户映射区域打开的文件”错误，不能算完整通过；核对资源文件已按原字节恢复后，单独重跑 17 项破坏检查全部通过（`image-tools-invariant-retry.log`）。最终完整入口使用相同构建产物运行 `runTests.ps1 -SkipBuild`，再次完整通过。跳过的是重复构建，不是回归测试。

## 中间失败与未验证项

1. 第一轮完整回归的 SVG 采样包含两个不同文件，不是同一图片的单纯百分比变化。已改用内容哈希相同的独立单文件目录，仍保留同一图片百分比必须稳定的断言；原日志为 `image-tools-full-tests.log`。
2. 第二轮执行中加入用户新反馈的恢复边框问题，主动停止该轮；不将 `image-tools-final-tests.log` 算作完整通过。
   随后一轮在“第五张恢复窗口大小”旧断言失败：旧测试强求宽高都达到工作区90%，与本次“不改图片倍率”的规则冲突。新断言按退出前真实图片尺寸/缩放区间确定窗口大小，并另外要求倍率不变，不能简单删掉尺寸校验。
3. 一次新增桌面色块自检返回 `picker=0`，当时没有更细诊断；补充诊断后连续三轮通过，原因未确定，不宣称完全消除环境时序风险。
4. 桌面操作工具列出窗口后连续发生绑定错误（`window id ... no longer belongs ...`），已停止该工具的人工坐标操作。不能把原生控件自检说成人工视觉验收。
5. 真实 Win10 4K/200%、混合 DPI 多屏、HDR，以及 Explorer 注册/缓存端到端仍未在当前环境验证。192/288 DPI 的几何单元测试不能代替真实屏幕。
6. 参考论坛和参考图片链接本轮读取失败；界面基于文字需求实现，未声称已经逐像素参照这些图片。

# 双击到清晰图：五款看图软件实测

用 `measure-open-to-sharp.ps1` 量的，2026-09-24，Win11 26200 / 本机。
原始明细在 `artifacts/release-gate/open-to-sharp-*.csv`。

## 量的是什么

判定完全靠读屏幕像素，对五个软件一视同仁，三个时间点都从进程启动算起：

| 列 | 含义 |
| --- | --- |
| 窗口 | 属于该程序的窗口第一次可见 |
| 出图 | 窗口里第一次出现「有内容的画面」（细节量迈过门槛，白底不算） |
| 清晰图 | 画面最后一次变化，此后连续 2.5 秒纹丝不动 |

「清晰图」取最后一次变化而不是第一次稳定，是这套量法的关键。YeImageViewer 和
GuoheView 对大图是渐进加载：先秒出一张缩略预览，再在后台解完原图换上去。预览本身是
静止画面，按「连续几帧不变」判定会在预览那一刻就宣布加载完成——数字好看，
可用户盯着的还是糊图。JarkViewer 相反，解完之前窗口一片空白，第一次画出来就是清晰图。
两种策略只有用「画面彻底不动」这把尺子量才能放在一起比。

另外记录首帧和末帧的**细节量**（相邻像素灰度差的均值），用来证明末尾那次变化确实是
「变清晰」而不是某个控件闪了一下。

## 怎么读这张表

**出图快是我们的强项。** 100MP 级别下 234 ms 就有画面，比 JarkViewer 的 857 ms 快
3.7 倍；291 MB 那张更悬殊，219 ms 对 2397 ms，差 11 倍。这段时间里 JarkViewer 窗口
是全白的，用户除了等没有别的事可做。

**清晰图到位我们比 JarkViewer 慢。** 100MP 级别慢约 530 ms（1391 对 857），
291 MB 那张慢约 400 ms（2792 对 2397）。十张图无一例外，不是抖动。原因还没定位，
预览线程与解码线程抢 CPU 是首要嫌疑，但没有实测支撑，先记在这里。

**GuoheView 和 2345看图王 那两个 ※ 要打问号。** 它们报出来的「清晰图」在 190–400 ms
之间，而且全程细节量不再变化。细节量本身不跨软件可比（窗口大小和缩放比例不同），
但同一张图上 YeImageViewer 与 JarkViewer 的终值总是收敛到同一水平
（124 MB 那张：24.33 对 24.78），GuoheView 与 2345看图王 的终值却始终低 30–40%
（15.65 和 13.70），并且从第一帧起就没动过。291 MB 那张更明显：2345看图王 的终值
3.92，正好落在我们**预览**的细节量区间（3.02）。两家很可能一直显示的是降采样版本。
要坐实这个判断得把每张图逐一放到 100% 逐像素比对，这次没做，所以只写成疑点。

**ImageGlass 全面落后**，窗口就要 421 ms，出图要 2 秒，且确实有渐进加载
（细节 0.4 → 7.55~39.81）。

## 和视频对照

用户录的对比视频（`视频1.mp4`，远程桌面录制，moon_81M.png）：

| | 视频（从双击算起） | 本机实测（从进程启动算起） |
| --- | ---: | ---: |
| YeImageViewer 出图 | 240 ms | 219 ms |
| YeImageViewer 清晰图 | ≈2860 ms | 2792 ms |
| JarkViewer 出图 | ≈2420 ms | 2397 ms |

两边对得上。视频里多出来的几十毫秒是 shell 解析文件关联的开销，双击比直接启动多这一段。

## 复现

```powershell
# 三张超大图，五个软件
./tools/image-test-runner/measure-open-to-sharp.ps1 -ImageDir "test\bigimage"

# 100MP+ 真实图
./tools/image-test-runner/measure-open-to-sharp.ps1 `
    -ImageDir "test\corpus\_local\07-extreme-png\02_Real_100MP_Plus"

# 只比两家、只跑一轮，快速看一眼
./tools/image-test-runner/measure-open-to-sharp.ps1 `
    -Image "test\bigimage\moon_81M.png" `
    -Viewer "x64\Release\YeImageViewer.exe","D:\software\JarkViewer.exe" -Repeats 1
```

跑的时候屏幕不能锁，远程桌面不能最小化——读不到像素会直接记 SKIPPED（退出码 3）。
测量过程会反复抢前台，期间别操作鼠标键盘。

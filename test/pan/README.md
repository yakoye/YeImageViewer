# 拖拽与高 DPI 设置回归夹具

`association-200pct-reported.png` 是用户提交的设置页复现截图，仅包含软件界面，用于记录 Win10、4K、200% 下网格挤在搜索框左侧的真实缺陷。自动测试不依赖截图相似度，而是经过生产 DPI 消息和点击路径核对绘制位置、按钮响应及实际注册表结果。

最小图片由 `scripts/test-viewing-regressions.ps1` 在隔离临时目录生成：

- 300×6000 PNG：顶部红色 200 行，底部蓝色 200 行，其余灰色，用于长图顶部起点、倍率、单轴及双轴边界。
- 惯性专项使用同尺寸 PNG，顶部红条增加到 400 行，用实际屏幕像素核对松手后红色标记继续移出视口；其余测试仍使用原 200 行红条。
- 两张 4000×3000 PNG：用于「默认实际大小」即时、切图和重启生效，排除小图本身就在 100% 的假通过。
- 不同尺寸、不同颜色的页面及 100 页文件集：用于连续阅读、配对、切图和有界缓存。
- HKCU 沙箱：随机且受限于 `Software\YeImageViewerTests\Native-<32位十六进制>`，生产注册代码实际写入；测试读回后清理。不改真实 UserChoice。

已有修复前失败证据存于本机 `artifacts/`：关联布局在 120 DPI 失败、滚轮选择框在 120 DPI 失败、默认 100% 被覆盖、连续阅读鼠标捕获被重复调用取消、快速连续拖动误触双击。策略单元测试还覆盖消息合并后慢拖不能被误算为快拖。脚本只运行自己复制的 EXE／DB／图片，不污染开发配置。

用户工具栏截图含桌面背景，不作为仓库夹具提交。参考位置已转为布局断言：垂直翻转 → 手掌＋倍率 → 右移的分隔线 → 上一张。

## 键盘方向复现素材

`keyboard-directions.svg` 是 1600 × 1600 灰底图，中间有 60 × 60 红色定位块。`test-viewing-regressions.ps1 -KeyboardPanOnly` 用它检查普通窗口、沉浸窗口、旋转后 W 上／S 下／A 左／D 右的实际屏幕位移及连续按键，并确认改绑 F5 后保存且原 W 不再生效。修复前会在首个 W 向上位移断言失败；源码默认键位本身正确，错误在动作的位移符号。

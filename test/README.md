# 回归测试素材

此目录保存曾触发真实缺陷的原始文件。新增素材时，应同时在根目录的 `runTests.ps1` 中加入自动化回归步骤，并记录缺陷现象和预期行为。

## format corpus 格式解码测试集

- `format corpus/manifest.tsv` 登记除暂缺可靠样本的 LEP 外全部 `ImageDatabase::supportExt` 扩展名，并锁定 SHA-256、尺寸、最少帧数和图片类型。
- `format corpus/SOURCES.md` 记录网络素材的上游 URL、固定 commit、许可证和本地生成方式；原生样本优先来自 OpenCV、libavif、libheif、libjxl 和 BLP 解码器的官方测试仓库。
- `runTests.ps1` 使用 `YeImageViewer.exe --decode-probe` 逐文件走正式解码分派；错误提示占位图、错误退出、尺寸或帧数不符都会使回归失败，全程不创建可见窗口。
- 本测试集在建立时发现并锁定了两个真实问题：默认环境下 EXR 被 OpenCV 关闭，以及已声明的 Sun Raster (`.ras`/`.sr`) 没有可用解码路径。

## Image crash/dji_export_photo_20260809221510044.jpg

- 来源：用户提供的 DJI MotionPhoto 原图。
- SHA-256：`00E55EF88EF3897D52D950839C676508D21F3D26AA0D549F8B4CFA96630FFC72`
- 历史缺陷：内嵌视频的 H.264 像素格式无法识别，FFmpeg `libswscale` 断言使程序以 `0xC0000409` 退出。
- 预期行为：无法解码内嵌视频时安全降级为静态 JPEG，窗口保持打开并正常响应。

## HDR 色彩通道回归

- 上游问题：[`jark006/JarkViewer#45`](https://github.com/jark006/JarkViewer/issues/45)。
- 历史缺陷：Radiance HDR 的 RGB 数据被当作 BGRA 显示，表现为红色与蓝色互换。
- 对比图：`HDR color error/HDR_compared.png`，SHA-256 为 `8010D5E627002BEE7591B86EF4BE965872C66C397F402F99F59EBF5D52C8F49D`。
- 原始文件：`HDR color error/HDR.hdr`，2560×1600，SHA-256 为 `1A1A661E0A22BECBE019B6C095004315351F28600D9BD7600BD933BEB351E5D5`。
- 自动化方式：`YeImageViewerTests` 先用内存中的纯红、纯蓝最小 Radiance HDR 验证精确 BGRA 通道顺序，再解码真实原图并验证尺寸和红/蓝通道统计关系；`runTests.ps1` 会先校验真实原图哈希，防止夹具被意外替换。

## 背景选择回归

- 复用透明矢量图 `SVG Blurring/SittingHuman.svg` 验证右键菜单中的“透明、白色、黑色、毛玻璃”四种背景。
- 透明棋盘格固定使用 12×12 像素单元和 `#EBEBEB / #F5F5F5` 两种低反差灰色，深浅主题显示一致。
- 预期行为：透明模式显示棋盘格，白/黑模式精确合成透明像素，毛玻璃模式将预乘 Alpha 图像交给 Windows DWM 桌面亚克力合成；不支持的系统回退为主题底色。
- 自动化方式：`YeImageViewerTests` 对四种背景和半透明像素做精确像素断言；`runTests.ps1` 打开真实 SVG 并依次切换四种菜单命令，验证窗口始终存活且可响应。

## 浏览界面、悬浮工具条与 Esc 回归

- 复用 `SVG Blurring/SittingHuman.svg` 验证普通与沉浸窗口的统一浏览界面和窗口状态恢复。
- 预期行为：参考设计的底部工具栏固定居中，包含上一张、下一张、左/右旋转、水平/垂直翻转、适应窗口、实际大小、沉浸显示、收藏、复制、删除、设置及缩放控制；左右两侧 40×40 翻页按钮与工具栏联动显示。
- 工具栏只允许由可见工具栏本体或左右按钮的精确区域触发，不允许整条底边或宽屏幕边缘形成隐形热区；窄窗口下工具栏必须等比缩小且不越界。
- “Esc关闭图片”开启时，沉浸与普通窗口按 Esc 都直接关闭；关闭时不会先退回普通窗口。选项关闭时保持退出沉浸、退出全屏、恢复最大化和普通窗口忽略的旧逻辑。
- 图片旋转状态按规范化完整路径保存；重新构造状态存储后必须恢复，回到 0° 时删除多余记录，损坏的状态文件安全回退为 0°。
- 打开图片先进入目标显示器工作区的无边框沉浸预览：小图按 DPI 逻辑 100% 显示，横图受 90% 宽度和 82.5% 高度限制，竖图只受 90% 宽度限制并允许高度溢出；超过 16:9 的长竖图从顶部开始显示。
- 单击图片保持沉浸预览并允许拖动；单击图片外背景空白或按 `Esc` 时，按退出瞬间的当前图片及工作区 90% 上限确定带边框窗口；退回后切换图片不改变外框。
- 退回窗口必须恢复启用、激活、键盘焦点和鼠标状态，标题栏关闭必须真正销毁窗口与进程；设置窗口固定为 `620 × 620` 客户区，所有标签页使用 16 像素 Segoe UI/ClearType，超出内容通过滚动条浏览。
- `F2` 不再打开设置窗口；设置页窗口级回归改用菜单命令触发。
- 沉浸模式的图片外区域使用约 60% 不透明的黑色 DirectComposition 客户区透出桌面；普通窗口的图片外区域固定为不透明 `#7F7F7F`，拉大窗口后保持一致。用户背景选择只作用于图片区域，右上角关闭按钮必须常驻，普通窗口最大化请求必须重新进入相同的沉浸路径。
- 设置窗口在沉浸图片上方移动后，主窗口必须保持无边框、响应和稳定合成；退回普通窗口后继续使用透明合成，同时恢复标题栏、缩放边框和完整鼠标交互。
- “记住最后使用的显示器”默认开启；设备名匹配忽略大小写，目标显示器断开或选项关闭时回退主显示器，负坐标窗口位置可往返恢复并被限制在工作区内。
- 滚轮组合交互默认是普通滚轮上下平移、`Ctrl + 鼠标滚轮`缩放、`Shift + 鼠标滚轮`左右平移，同时按下 Ctrl 与 Shift 时 Ctrl 优先；三种动作和全部键盘快捷键都允许在设置中改动并持久化。
- 自动化方式：`YeImageViewerTests` 校验 Picasa 示例尺寸、横竖图策略、沉浸半透明黑色与普通窗口 `#7F7F7F` 的精确像素、退回客户区、关闭按钮、设置固定尺寸和滚动边界、Windows 原生文字策略、精简图片信息字段与半透明遮罩、滚轮组合键方向和优先级、18 个浏览图标、设置页和工具栏全部按钮的正式命令路由、窄窗口缩放、翻转/旋转坐标、九种尺寸应用图标、旋转状态重载和 Esc 决策优先级；`runTests.ps1` 验证 EXE 版本为 `1.36.29.0`、嵌入 Commit ID、图标资源哈希、Windows PowerShell 5.1 安装脚本编码、无副作用安装复制，并在真实窗口中回归配置 Esc 的沉浸/普通关闭、沉浸切到第 5 张后按当前图片尺寸退回、DirectComposition 客户区、三种滚轮默认动作、无边框启动、图片区不退回、背景退回、交互恢复、标题栏关闭、最大化进入沉浸、常驻关闭按钮防穿透、设置窗口跨标签固定 `620 × 620`、设置窗口跨图片移动、固定窗口切图、全屏、普通窗口 Esc 以及居中工具栏精确悬停。
- `current image restore/01-small.svg` 至 `05-tall-capped.svg` 是窗口恢复专用最小夹具：第 1 张提供小窗口基线，第 5 张采用高宽比 2:1 的超长竖图，用于验证超过 16:9 后从顶部浏览，并在退出沉浸时改用当前图片、应用 90% 上限。

## 启动页与外部图片编辑器回归

- 未传入图片时显示纯代码绘制的功能启动页，不再依赖模糊的预览位图；文字和卡片按当前显示器 DPI 原生生成并保持 100%，禁止先画低分辨率页面再放大。“打开一张图片”是可点击按钮，并展示当前有效的打开、浏览、缩放和更多操作提示。
- 右键“编辑图片”子菜单显示用户实际配置的应用，最多 10 个；菜单文案固定为“在 画图”这类无括号格式。名称为空或全空格时自动使用可执行文件名，用户名称和 Unicode 路径保存在程序同目录的 `YeImageViewer.editors.ini`。
- “选择并设置应用...”会选择 EXE、确认显示名称、立即用该程序打开当前图片；之后可直接从右键子菜单再次打开。设置页支持添加、改名、更换路径和移除。
- 自动化方式：`YeImageViewerTests` 验证启动页布局、96/144 DPI 原生画布、名称回退、菜单精确文案、10 项上限、重复路径更新、Unicode INI 往返及带空格图片参数；`runTests.ps1` 在主显示器真实打开启动页并点击按钮，以程序自身副本验证选择器取消与图片路径传递，并在本机已安装时通过正式右键命令让 Paint、RIOT 打开真实 PNG。

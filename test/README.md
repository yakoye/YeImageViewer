# 回归测试素材

此目录保存曾触发真实缺陷的原始文件。新增素材时，应同时在根目录的 `runTests.ps1` 中加入自动化回归步骤，并记录缺陷现象和预期行为。

## format corpus 格式解码测试集

- `format corpus/manifest.tsv` 登记除暂缺可靠样本的 LEP 外全部 `ImageDatabase::supportExt` 扩展名，并锁定 SHA-256、尺寸、最少帧数和图片类型。
- `format corpus/SOURCES.md` 记录网络素材的上游 URL、固定 commit、许可证和本地生成方式；原生样本优先来自 OpenCV、libavif、libheif、libjxl 和 BLP 解码器的官方测试仓库。
- `runTests.ps1` 使用 `YeImageViewer.exe --decode-probe` 逐文件走正式解码分派；错误提示占位图、错误退出、尺寸或帧数不符都会使回归失败，全程不创建可见窗口。
- 本测试集在建立时发现并锁定了两个真实问题：默认环境下 EXR 被 OpenCV 关闭，以及已声明的 Sun Raster (`.ras`/`.sr`) 没有可用解码路径。

## Image crash/dji_export_photo_20260809221510044.jpg

- 来源：用户提供的 DJI MotionPhoto 原图。
- SHA-256：`00E55EF88EF3897D52D950839C676508D21F3D26AA0D549F8B4CFA96630FFC72`
- 历史缺陷：内嵌视频的 H.264 像素格式无法识别，FFmpeg `libswscale` 断言使程序以 `0xC0000409` 退出。
- 预期行为：无法解码内嵌视频时安全降级为静态 JPEG，窗口保持打开并正常响应。

## HDR 色彩通道回归

- 上游问题：[`jark006/JarkViewer#45`](https://github.com/jark006/JarkViewer/issues/45)。
- 历史缺陷：Radiance HDR 的 RGB 数据被当作 BGRA 显示，表现为红色与蓝色互换。
- 对比图：`HDR color error/HDR_compared.png`，SHA-256 为 `8010D5E627002BEE7591B86EF4BE965872C66C397F402F99F59EBF5D52C8F49D`。
- 原始文件：`HDR color error/HDR.hdr`，2560×1600，SHA-256 为 `1A1A661E0A22BECBE019B6C095004315351F28600D9BD7600BD933BEB351E5D5`。
- 自动化方式：`YeImageViewerTests` 先用内存中的纯红、纯蓝最小 Radiance HDR 验证精确 BGRA 通道顺序，再解码真实原图并验证尺寸和红/蓝通道统计关系；`runTests.ps1` 会先校验真实原图哈希，防止夹具被意外替换。

## 背景选择回归

- 复用透明矢量图 `SVG Blurring/SittingHuman.svg` 验证右键菜单中的“透明、白色、黑色、毛玻璃”四种背景。
- 透明棋盘格固定使用 12×12 像素单元和 `#EBEBEB / #F5F5F5` 两种低反差灰色，深浅主题显示一致。
- 预期行为：透明模式显示棋盘格，白/黑模式精确合成透明像素，毛玻璃模式将预乘 Alpha 图像交给 Windows DWM 桌面亚克力合成；不支持的系统回退为主题底色。
- 自动化方式：`YeImageViewerTests` 对四种背景和半透明像素做精确像素断言；`runTests.ps1` 打开真实 SVG 并依次切换四种菜单命令，验证窗口始终存活且可响应。

## 浏览界面、悬浮工具条与 Esc 回归

- 复用 `SVG Blurring/SittingHuman.svg` 验证普通与沉浸窗口的统一浏览界面和窗口状态恢复。
- 预期行为：参考设计的底部工具栏固定居中，包含上一张、下一张、左/右旋转、水平/垂直翻转、适应窗口、实际大小、沉浸显示、收藏、复制、删除、设置及缩放控制；左右两侧 40×40 翻页按钮与工具栏联动显示。
- 工具栏只允许由可见工具栏本体或左右按钮的精确区域触发，不允许整条底边或宽屏幕边缘形成隐形热区；窄窗口下工具栏必须等比缩小且不越界。
- “Esc关闭图片”开启时，沉浸与普通窗口按 Esc 都直接关闭；关闭时不会先退回普通窗口。选项关闭时保持退出沉浸、退出全屏、恢复最大化和普通窗口忽略的旧逻辑。
- 图片旋转状态按规范化完整路径保存；重新构造状态存储后必须恢复，回到 0° 时删除多余记录，损坏的状态文件安全回退为 0°。
- 打开图片先进入目标显示器工作区的无边框沉浸预览：小图按 DPI 逻辑 100% 显示，横图受 90% 宽度和 82.5% 高度限制，竖图只受 90% 宽度限制并允许高度溢出；超过 16:9 的长竖图从顶部开始显示。
- 单击图片保持沉浸预览并允许拖动；单击图片外背景空白或按 `Esc` 时，按退出瞬间的当前图片及工作区 90% 上限确定带边框窗口；退回后切换图片不改变外框。
- 退回窗口必须恢复启用、激活、键盘焦点和鼠标状态，标题栏关闭必须真正销毁窗口与进程；设置窗口固定为逻辑 `620 × 620` 客户区并按所在显示器 DPI 放大到对应物理尺寸，所有标签页使用 16 像素 Segoe UI/ClearType，超出内容通过滚动条浏览。
- 窗口标题以文件名开头，其后依次是状态、`[序号/总数]`、缩放百分比、像素尺寸、文件大小和旋转。Windows 标题栏从右侧截断，任务栏预览和 Alt+Tab 也只显示开头一段，文件名必须排在最前才不会被切掉。
- 图片信息面板的配色跟随界面主题：深色主题恒用深色面板，浅色主题恒用浅色面板，不再按面板底下的画布亮度自适应（此前深色主题下看白底图仍会得到浅色面板）。面板底色 alpha 为 `0xD1`，深色面板压在纯白图片上文字对比度约 9:1。
- `F2` 不再打开设置窗口；设置页窗口级回归改用菜单命令触发。
- 沉浸模式的图片外区域使用约 60% 不透明的黑色 DirectComposition 客户区透出桌面，不受背景设置影响。普通窗口的图片外区域跟随用户的背景选择：白、黑、毛玻璃铺满整个客户区，透明棋盘格也铺满整窗（此前该区域恒为不透明 `#7F7F7F`，背景设置只作用于图片自身的透明像素，用户改了设置看不出变化）。右上角关闭按钮必须常驻，普通窗口最大化请求必须重新进入相同的沉浸路径。
- 设置窗口在沉浸图片上方移动后，主窗口必须保持无边框、响应和稳定合成；退回普通窗口后继续使用透明合成，同时恢复标题栏、缩放边框和完整鼠标交互。
- “记住最后使用的显示器”默认开启；设备名匹配忽略大小写，目标显示器断开或选项关闭时回退主显示器，负坐标窗口位置可往返恢复并被限制在工作区内。
- 滚轮组合交互默认是普通滚轮上下平移、`Ctrl + 鼠标滚轮`缩放、`Shift + 鼠标滚轮`左右平移，同时按下 Ctrl 与 Shift 时 Ctrl 优先；三种动作和全部键盘快捷键都允许在设置中改动并持久化。
- 「适合窗口」与「实际大小」成对提供键盘快捷键，默认分别是 `5` 和 `1`，小键盘 `5`、`1` 在保持默认绑定时同样生效。快捷键存储按动作枚举下标定位，新动作只能追加在末尾；版本升级必须是增量的——只给新动作补默认键位，用户改过的绑定一律保留，新动作的默认键位若已被占用则留空而不是抢走。
- 浮动工具栏、沉浸模式关闭按钮和缩放指示器按窗口所在显示器的 DPI 缩放。进程声明了 `PerMonitorHighDPIAware`，Windows 不会代为拉伸，此前这些控件只按窗口宽度缩放且封顶 100%，200% 缩放下只有应有尺寸的一半；窗口宽度不足时仍按宽度等比收缩。工具栏上的缩放百分比文字、关闭按钮叉号的臂长与线宽都跟随同一比例。
- 工具栏 SVG 图标按基准尺寸的 4 倍渲染，绘制时只做 `INTER_AREA` 缩小，保证高 DPI 下放大的图标依然锐利；此前按 20×20 渲染再拉大，高分屏上边缘发糊。
- 设置窗口与打印预览按 DPI 放大时受工作区上限约束：打印预览逻辑高 950，200% 缩放就是 1900 物理像素，很多显示器放不下，此时缩放比会回退到工作区装得下的最大值，下限为 96 DPI（即不小于按物理像素布局的旧行为）。画布始终是逻辑尺寸，贴图时用 `HALFTONE` 拉伸，鼠标坐标按同一比例换算回逻辑空间，命中测试才不会错位。
- 自动化方式：`YeImageViewerTests` 校验 Picasa 示例尺寸、横竖图策略、沉浸半透明黑色的精确像素、普通窗口留白跟随四种背景选择（含棋盘格铺满整窗）、192 DPI 下工具栏/关闭按钮/缩放指示器等比放大与窄窗口回缩、快捷键存储的增量版本升级、退回客户区、关闭按钮、设置固定尺寸和滚动边界、Windows 原生文字策略、精简图片信息字段与半透明遮罩、滚轮组合键方向和优先级、18 个浏览图标、设置页和工具栏全部按钮的正式命令路由、窄窗口缩放、翻转/旋转坐标、九种尺寸应用图标、旋转状态重载和 Esc 决策优先级；`runTests.ps1` 验证 EXE 版本为 `1.36.30.0`、嵌入 Commit ID、图标资源哈希、Windows PowerShell 5.1 安装脚本编码、无副作用安装复制，并在真实窗口中回归配置 Esc 的沉浸/普通关闭、沉浸切到第 5 张后按当前图片尺寸退回、DirectComposition 客户区、三种滚轮默认动作、无边框启动、图片区不退回、背景退回、交互恢复、标题栏关闭、最大化进入沉浸、常驻关闭按钮防穿透、设置窗口跨标签固定逻辑 `620 × 620`（按 DPI 换算物理尺寸）、标题以文件名开头、设置窗口跨图片移动、固定窗口切图、全屏、普通窗口 Esc 以及居中工具栏精确悬停。
- `current image restore/01-small.svg` 至 `05-tall-capped.svg` 是窗口恢复专用最小夹具：第 1 张提供小窗口基线，第 5 张采用高宽比 2:1 的超长竖图，用于验证超过 16:9 后从顶部浏览，并在退出沉浸时改用当前图片、应用 90% 上限。

## 启动页与外部图片编辑器回归

- 未传入图片时显示纯代码绘制的功能启动页，不再依赖模糊的预览位图；文字和卡片按当前显示器 DPI 原生生成并保持 100%，禁止先画低分辨率页面再放大。“打开一张图片”是可点击按钮，并展示当前有效的打开、浏览、缩放和更多操作提示。
- 右键“编辑图片”子菜单显示用户实际配置的应用，最多 10 个；菜单文案固定为“在 画图”这类无括号格式。名称为空或全空格时自动使用可执行文件名，用户名称和 Unicode 路径保存在程序同目录的 `YeImageViewer.editors.ini`。
- “选择并设置应用...”会选择 EXE、确认显示名称、立即用该程序打开当前图片；之后可直接从右键子菜单再次打开。设置页支持添加、改名、更换路径和移除。
- 自动化方式：`YeImageViewerTests` 验证启动页布局、96/144 DPI 原生画布、名称回退、菜单精确文案、10 项上限、重复路径更新、Unicode INI 往返及带空格图片参数；`runTests.ps1` 在主显示器真实打开启动页并点击按钮，以程序自身副本验证选择器取消与图片路径传递，并在本机已安装时通过正式右键命令让 Paint、RIOT 打开真实 PNG。

## 重命名对话框输入法回归

- 主看图窗口靠单键快捷键工作，输入法按窗口摘除（`ImmAssociateContext(hwnd, nullptr)`）；设置窗口与打印窗口同理。重命名对话框是独立顶层窗口（窗口类 `YeImageViewerRenameWnd`），保留默认输入上下文，因此可以输入中文。
- 禁止使用 `ImmDisableIME`：它作用于整个线程且调用后无法撤销，进程从此不再加载任何输入法，搜狗、微信输入法、小狼毫、PiInput 一概失效，重命名框也就打不出中文。
- 自动化方式：`runTests.ps1` 先在源码中确认没有 `ImmDisableIME` 调用、`D3D11App` 与 `MatWindow` 保留按窗口摘除、`main.cpp` 不摘除重命名对话框；再启动真实进程，用 `ImmGetDefaultIMEWnd` 确认线程仍有默认输入法窗口（线程级禁用时该句柄为 0，这正是修复前后的区别），并确认 F2 打开的重命名框把键盘焦点交给编辑框、取消后主窗口恢复可交互。

## 打开方式、双击与拖动交互回归

- 设置页「常规」新增四组选项，均存放在 `SettingParameter::reserve` 的高位区（`ViewerOptions::STORAGE_BASE` 起），避开快捷键占用的低位区；设置文件固定 4096 字节、成员顺序不可改，新配置只能落在 reserve 里。旧设置文件这块区域是全零，magic 对不上时按默认值铺一遍，不影响其他既有配置。
- 打开图片方式三选一：沉浸预览（默认，无边框覆盖工作区）、窗口适应图片（普通窗口，客户区按图片原尺寸，超出工作区 90% 上限时等比缩小并保持宽高比）、记住上次大小（普通窗口，沿用上次关闭时保存的窗口矩形）。后两种都留在带边框的普通窗口里，区别只是尺寸来源。
- 双击图片的动作三选一，默认切换全屏（与既有行为一致）。选「最大化/还原」时，全屏状态下双击先退出全屏，沉浸预览下双击退回普通窗口——这两种状态都没有「最大化」可言。注意最大化不能走 `OnMaximizeRequested()`，那条路径是进入沉浸预览而不是最大化窗口。
- 两侧翻页箭头默认隐藏，打开后鼠标移到窗口左右边缘才出现，点击翻页；只在图片多于一张时参与命中。箭头的命中判定排在唤出工具栏的热区之前，否则会被那片很大的热区盖住。
- 拖动图片默认在图片没有可平移余量时移动窗口（缩放后的图片任何一边都没超出窗口即视为无余量），放大到超出窗口后恢复平移；沉浸预览铺满工作区，移动窗口没有意义，那里始终保持平移。可在设置中改回「仅平移图片」。窗口拖动交给系统的 `WM_NCLBUTTONDOWN` + `HTCAPTION` 循环，不自己算偏移。
- `SettingCommand::resolve` 里的 `optionCounts` 必须与 `GENERAL_RADIOS` 数量逐项对应，少一项就会越界取到 0 并触发整数除零；生产代码与单元测试两侧都用 `static_assert` 钉住数量。
- 自动化方式：`YeImageViewerTests` 校验选项默认值、越界值回落、旧设置文件补种、新配置区与快捷键区不重叠、拖动改为移窗的三个前置条件、沉浸与非沉浸的打开方式判定、窗口适应图片的 1:1 与上限缩放、两侧箭头的位置与 DPI 缩放、箭头开关对命中的影响，以及设置页全部单选组（含新增四组）的命令路由。

## 设置页常规标签原生控件回归

- 设置页「常规」的开关与单选改用 Win32 原生控件。自绘画布只能按逻辑尺寸绘制再拉伸到物理客户区，高 DPI 下文字必然发虚；原生控件由系统按物理像素渲染，天生清晰，还白得键盘导航与无障碍。控件挂在一个可滚动的子面板上，滚动时整体平移面板。
- 面板高度与外部编辑器卡片的起点对齐：那部分仍是自绘的，两者按同一个 `scrollOffset` 滚动，高度对不上就会互相遮挡或错位。
- 必须声明 ComCtl32 v6 依赖并调用 `InitCommonControlsEx`，否则原生控件是 Win95 时代的经典外观。
- 深色主题有两处坑，缺一不可：其一，进程要先通过 uxtheme 的序号 135 导出声明允许深色，comctl32 才会改用深色主题取色；其二，启用视觉样式后勾选框与单选钮自己绘制文字，不再经过 `WM_CTLCOLORSTATIC`，而 `SetWindowTheme` 对 BUTTON 的文字不起作用——实测未选中项会被画成深灰，在深色背景上几乎看不见。因此这两类控件改为 `BS_OWNERDRAW`：方框仍交给系统主题绘制以保住现代外观，文字自己按当前主题着色。
- `BS_OWNERDRAW` 与 `BS_AUTOCHECKBOX` 的样式位冲突，按钮不再自动翻转选中态，绘制时也读不到可靠的 `BM_GETCHECK`，选中状态由面板自己缓存，点击时手动取反。
- 面板的显隐与滚动位置只能在 UI 线程调整：`drawingUI()` 跑在 `MatWindow` 的绘制线程，`SetWindowPos`/`ShowWindow` 在那里调用是错的，因此同步挂在每次绘制完成的 `WM_MATWINDOW_DRAW_DONE` 上。
- 自绘的常规页命中与绘制代码保留为回退路径：面板创建失败时仍要能操作。真实鼠标点击由上层原生控件接管，而 `runTests.ps1` 给设置窗口发的是合成的 `WM_LBUTTONDOWN`，走的正是这条回退路径，所以配置 Esc 的真实窗口回归依然有效。
